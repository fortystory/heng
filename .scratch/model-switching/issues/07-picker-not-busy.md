> *This was generated by AI during triage.*

> 规格：[`../spec.md`](../spec.md) §6。本票是给 AFK agent 的契约；行为以本票为准。

**Category:** bug
**Summary:** 打开模型 / 思考强度选择器时，左栏「衡」标记会扫光、状态行显示「工作中」、对话区
出现「正在思考」—— 而那一刻模型什么都没在跑。

**Current behavior:**

按 `ctrl-t`（或点状态行那两格）开出选择器，浮层开着的那段时间里，前台会话在宿主表的三态里
是 `RunningTurn`（正在跑一个回合），于是界面按「在跑」说话。

链路是：前端手势 `FrontEndEvent::OpenPicker` → 主循环转给前台会话 → `CliCommand::Gesture` →
会话 actor 的 `gesture()` → `open_picker()` → `console.picker(...).await` 等人答。

问题出在**宿主对每一条命令都置 `RunningTurn`**：`SessionHost::adopt_with` 起的那个 task 在
`actor.act(...)` 之前把状态置成 `RunningTurn`，命令办完才回 `Idle`。而开选择器正是一条
「手势」命令，它在里面等人答 —— 于是选器开着多久，会话就「在跑」多久。

`TuiState::busy()` 读的就是这个三态，于是三张脸一起出现：

- 左栏「衡」标记扫光（`state.busy().then_some(state.pulse)`）；
- 状态行的月亮走月相、状态词从「就绪」变成「工作中」；
- 对话区末尾多出一行「正在思考.」。

同一根因也落在别的读数上：页顶「M 个在跑」数着它、流程页把这一格画成在跑、外部面板上报
（herdr）说这个 agent 在忙。

**Desired behavior:**

选器开着时，前台会话是「空闲，等人」—— 模型那一刻没有在跑，界面就按空闲说话：

- 状态行显示静止的满月与「就绪」；
- 左栏「衡」标记不扫光；
- 对话区末尾没有「正在思考」那一行；
- 页顶「M 个在跑」不数这个会话，流程页不把它画成在跑。

选器其余行为一字不变：候选现算、↑↓ 与 `j`/`k` 移动、`Enter` 选中、`Esc` 取消、选中后切换生效。

**模型等人答的那些等待照旧算忙**：问卷、权限门、`ask_user_question` —— 那里模型真的停着，
三态是 `AwaitingHuman`，这一票不动它。

**一个回合真在跑时照旧算忙**：`RunningTurn` 照旧置着，页顶数它、退出闸门拒它、`Ctrl-C`
取消它。

**Key interfaces:**

- `SessionActor<C>`（`src/session/host.rs`）：加一个「这条命令是不是**一个回合**」的判断，宿主
  据此决定要不要把会话置成 `RunningTurn`。默认实现保守（当作回合），由各 actor 覆盖。
- `SessionHost::adopt_with`（同文件）：置 `RunningTurn` 的那一行按上面那个判断走；办完回
  `Idle` 的收尾不变。
- `CliActor`（`src/cli/interactive.rs`）：`CliCommand::Submit` / `ResumeGoal` / `Rollover` 是
  回合；`CliCommand::Gesture` 不是（它是手势：开选器、模式循环、改名、取消）。注意
  `ResumeGoal` 与 `Rollover` 里跑的是**目标循环**，它们算回合 —— 退出闸门仍要挡得住。
- 库那一侧的 `TurnActor`（`src/session/host.rs`）：`SessionCommand::Turn` 是回合；
  `RecordCommand` / `LoadSkill` / `Undo` / `SwitchModel` / `SwitchEffort` / `Cancel` 不是。
- `SessionState`（同文件）：三态本身**不改**（不加第四个状态）。`RunningTurn` 的含义照旧是
  「正在跑一个回合」—— 这一票收窄的是**置它的时机**，不是加一档。
- 渲染层不动：`TuiState::busy()` 照旧读三态，它只是第一次读到了对的值。

**Acceptance criteria:**

- [ ] 按 `ctrl-t` 开着选择器时，状态行显示静止的满月与「就绪」。
- [ ] 同一时刻左栏「衡」标记不扫光、对话区末尾没有「正在思考」。
- [ ] 同一时刻页顶「M 个在跑」不数这个会话。
- [ ] 选器取消（`Esc`）不产生切换；选中另一个模型之后状态行换名、下一回合用新模型（照旧）。
- [ ] 一个回合真在跑时：会话三态是 `RunningTurn`，页顶数它、退出闸门（`Ctrl-D` 双击）拒它、
      `Ctrl-C` 取消它。
- [ ] 问卷 / 权限门那种「模型等人答」的等待仍然算忙（三态 `AwaitingHuman`，状态行照旧说忙）。
- [ ] 目标循环跑着时（`/goal-new` 那一族），会话三态是 `RunningTurn`，退出闸门仍拒它退出。
- [ ] `cargo test` 全绿；`cargo clippy --all-targets` 无新增告警；`cargo fmt --check` 只留既有漂移。

**落地位置:**

按当前实现写的，改名或重构后按语义找：

- `src/session/host.rs`：`SessionActor` 加那个判断、`SessionHost::adopt_with` 按它置状态、
  `TurnActor` 覆盖它、`SessionState` 的文档注释（说清 `RunningTurn` 只在真跑回合时置）。
- `src/cli/interactive.rs`：`CliActor` 覆盖那个判断（`CliCommand` 的哪几个是回合）。
- `docs/tui-manual-checklist.md`：㊱ 那节加一条真机走查（选器开着时状态行仍说「就绪」）。

**测试:**

- **宿主层（主回归）**：一个 actor 在处理一条**非回合**命令时阻塞（等一个信号），断言这段
  时间里会话三态是 `Idle` —— 今天是 `RunningTurn`。
- **宿主层（不回归）**：同一条用例的回合版：actor 处理一条**回合**命令时阻塞，三态是
  `RunningTurn`。
- **前端层**：会话三态为 `Idle` 时前端的忙闲判据为假。既有那条「这个会话确实在跑」的用例
  旁边添一条空闲的。
- **真机**：pty 脚本按 `ctrl-t`，断言状态行仍是「就绪」、对话区没有「正在思考」。
  `scripts/tui-startup-check.py` 已有 pty 骨架（它自己回答光标位置查询），照它那套加一轮即可；
  只加进 `docs/tui-manual-checklist.md` ㊱ 的走查项也可以 —— 但那条走查项是「手感」，盯不住
  回归。

**明确不做:**

- `forward_gesture` 用全局 `host.running() > 0` 判忙那一条：后台会话在跑时，前台空闲也会被拒
  「这一回合跑完再切」。那是另一处判据的问题（该看前台会话自己的状态），不在这张票。
- 不加第四个会话状态，也不改三态词条。
- 不改选器浮层本身：画法、键位、候选规则、候选项现算那条纪律都照旧（`../spec.md` §8–§10）。
- 不改「模型等人答 = 忙」那条语义（`AwaitingHuman` 与退出闸门的口径都照旧）。

## 评论

- 2026-10-21 triage：维护者报告 ——「使用 ctrl-t 弹窗选择模型时，'衡'logo 和月亮都会进入
  '工作中'状态，对话窗口中也会有'正在思考..'字样」。已复现：pty 上按 `ctrl-t`，状态行是
  `🌓 工作中`、对话区是 `正在思考.`；按 `esc` 关掉浮层后恢复 `🌕 就绪`。
- 2026-10-21 根因：宿主对**每一条命令**置 `RunningTurn`，而开选器是一条手势命令、它在里面
  等人答 —— 于是浮层开着多久，会话就「在跑」多久。
- 2026-10-21 维护者定修法：**宿主层** —— 三态只在真跑回合时置（不新增状态，也不在渲染层给
  选器开特例）。
- 2026-10-21 顺带发现（不并入本票）：`forward_gesture` 用 `host.running() > 0`（全局计数）
  判忙 —— 后台会话在跑时，前台空闲也会被拒「这一回合跑完再切」。
