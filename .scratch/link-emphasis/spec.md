# 对话视图里的文件链接：上链接色，点开走文件查看器

Status: 2 done + 1 ready-for-walkthrough

- **来源**：2026-10-21 维护者的三条优化里的前两条（「用颜色区分单行代码和文件链接」「用文件查看器
  （nvim）打开文件链接」）。第三条（工具声明在轨迹里可见）另开一张 wayfinder 决策图：
  [`tool-declaration-visibility/`](../tool-declaration-visibility/seed.md)。
- **术语**：链接热区 / 文件查看器照 [`CONTEXT.md`](../../CONTEXT.md)；本 spec 新用
  **文件链接**（一段被认成工作区路径的候选）与**链接色**（`palette::LINK`）。
- **前置**：[`clickable-links/`](../clickable-links/spec.md)（候选怎么认、点一下怎么解析）、
  [`nvim-file-viewer/`](../nvim-file-viewer/spec.md)（文件查看器那一档）、
  [`tui-visual-language/`](../tui-visual-language/spec.md)（语义色板的两层分家）。

## 问题陈述

**一、文件链接与行内代码长得几乎一样。** 行内代码是静音灰（`CODE_QUIET`）；文件链接今天只有一条
下划线，颜色与正文一样（`PLAIN`）。于是 ``[`seed.md`](seed.md)`` 与 `seed.md` 在屏幕上分不出谁是谁
—— 前者是一条指向文件的链接，后者只是一段代码。维护者要的是**用颜色把这两者分开**。

**二、点开工作区文件链接走的不是界面里那扇门。** 今天的路径候选点一下交给宿主 `xdg-open`
（`src/render/opener.rs`）：终端被交出去一次，浏览器或文件管理器在 TUI 之外弹开。而左栏文件页
那一扇门（内置预览，或 `[ui] file_viewer = "nvim"` 的内嵌 nvim）已经在界面里，文件链接却没有走它。

## 方案（维护者 2026-10-21 定的三条）

1. **文件链接上链接色**：内容域新一档 `LINK`（`LightCyan`）。凡是**被认成工作区路径**的候选，
   在**正文那一档**里上链接色；**行内代码保持灰**。Markdown 链接（目标是文件）的标签与目标回显
   也上链接色。
2. **文件链接走文件查看器**：点一条工作区文件链接 → 与左栏文件页同一扇门（`[ui] file_viewer` 决定
   内置预览还是内嵌 nvim）。**URL 仍走 `xdg-open`**。
3. **工具声明那件事另开一张图**（不在本 spec 的范围内）。

## 实现决定

### §1 什么算「文件链接」，颜色落在哪里

判据**沿用** `src/render/links.rs` 的候选识别（`Target::Path`），不另写一套路径形状的规则。

颜色只落在**正文那一档**的候选上 —— 判据是**候选所在 span 有没有指定前景色**：**没有指定**
（`None`）才算正文。于是：

| 候选所在的地方 | 前景色 | 上不上链接色 |
| --- | --- | --- |
| 助手正文、用户发言、表格单元、列表 | 没有指定 | **上** |
| 工具输出 | `MUTED`（那是**过程**，静音档） | 不上 |
| 行内代码 | `CODE_QUIET` | 不上（**保持灰**） |
| 引用块 | `CODE_QUIET`（叙述灰） | 不上 |
| 代码块 | 语法色；没有语法色的那些**显式**说是「终端默认」（`Color::Reset`） | 不上 |

「行内代码保持灰」是这一版的第一条：它就是维护者要的那条区分。

**Markdown 链接**由渲染层单独画（它知道目标是文件还是 URL）：

- 目标是**文件路径** → **标签与目标回显**（` (seed.md)`）都上链接色。标签是行内代码时**也**上 ——
  「这是一个链接」比「这是一段代码」更该说清楚（这正是 ``[`seed.md`](seed.md)`` 这一形态）。
- 目标是 **URL** → 不上链接色（它不是文件链接；它走浏览器那一路）。
- **例外只有一处：引用块**。「引用里的一切都是叙述灰」是既有规矩（`src/render/markdown.rs` 的 `style()`），
  它**先于**这一档 —— 引用块里的链接标签与目标回显也保持叙述灰（链接仍有下划线、仍点得开）。

### §2 颜色值

- `palette::LINK = Color::LightCyan`，住在**内容域**（回答「这是什么」，不是「要不要注意」）。
- 与界面域 `DEBATERS[0]` 撞值是**刻意的**（域间允许撞值）；链接另有一层下划线，两层不打架。
- 它是内容域里**新加**的一档 —— `CODE_QUIET` 那一档（行内代码、引用条、**URL 链接**的目标回显、
  代码块的语言名、表格网格、语法里的注释与标点）**一个字不动**，只有**文件链接**升到 `LINK`。

### §3 点击 → 打开

- **`Target::Path`** → 在点击那一刻解析（**存在 + 落在工作区内**，今天的判据一字不动）→ 走
  **文件查看器**：与左栏文件页同一扇门（`open_file`：`[ui] file_viewer` 决定内置预览还是内嵌 nvim）。
- **目标是目录** → 仍旧走 `xdg-open`（内置预览读不了目录；这一档是「看文件」的）。
- **`Target::Url`** → 仍旧走 `xdg-open`（宿主侧 argv 直传，不经 shell）。
- 走**弹窗**那一路**不打印回执**（浮层本身就是回执；与左栏文件页同一纪律）。走 `xdg-open` 那一路
  的回执（`已打开 …` / `打开失败：…`）一个字不动。
- 这一条路**不过 `bash` 工具、不过权限门、不进沙箱** —— 与 `xdg-open` 同一条纪律：宿主侧动作，
  模型触发不了它。

### §4 边界

- 弹窗与详情覆盖层互斥（`open_file_viewer` 里已经先收掉详情）。
- 内嵌 nvim 起不来 → 回退内置预览（既有行为）。
- 平铺态：焦点格那一格走同一套（`follow_link` 是同一个函数）。

## 测试决定

- `links.rs` 单测：正文里的路径候选 → 前景色变 `LINK`；行内代码里的路径候选 → 仍是 `CODE_QUIET`；
  URL 候选 → 前景色不动。
- `markdown.rs` 单测：文件目标的链接 → 标签与目标回显都是 `LINK`；URL 目标的链接 → 不变；
  独立的行内代码 → `CODE_QUIET`。
- `tui.rs` 单测：点一条文件链接 → 弹窗/详情打开；点一条 URL → `open_request` 仍是那个 URL；
  点一个目录 → 仍是 `open_request`。
- 集成测试：对话视图里点一条工作区路径，界面上出现的是文件内容（内置预览那一档）。

## 明确不做

- **不给 URL 链接上链接色** —— 这一版只区分「文件链接」与「别的东西」。
- **不改 `xdg-open` 那条路本身**（URL 与目录仍走它）。
- **不动左栏文件页**的行为（它本来就是这一扇门）。
- **不做可写的文件查看器** —— 那一档只读（[ADR 0013](../../docs/adr/0013-nvim-file-viewer-is-an-alien-screen.md)）。
- **不给行内代码加别的颜色** —— 这一版它保持灰。
