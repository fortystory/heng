## 具体行为

1. **`docs/render.md`「可点链接」一节**：在「可点就是下划线」那一条之后补一条「**可点就是链接色**」
   （什么算文件链接、颜色落在正文那一档、行内代码保持灰、Markdown 链接的标签与回显），在「打开是
   宿主侧的动作」那一条之后补一条「**文件链接走文件查看器**」（与左栏文件页同一扇门、目录与 URL 仍走
   `xdg-open`、弹窗那一路不回执）。写的是**现状**，不搬 spec 的理由与备选方案。词表里用
   **文件链接** / **链接色**，别写「超链接」。
2. **`docs/tui-manual-checklist.md`**：一条走查，四个判断点（按现有条目的写法：编号、一句判断标准、
   怎么做）：① 对话里一句正文引用了 `README.md` → 那一段是链接色，同一段里的 `` `cargo test` ``
   仍是灰的；② 点那条路径 → 界面里升起的是文件内容（内置预览那一档）；③ `[ui] file_viewer = "nvim"`
   时点同一条路径 → 升起的是一屏 nvim；④ 点一条 URL → 仍然是浏览器弹开（终端外）。
3. **`CONTEXT.md`**：补一条**链接色**词条（若已有相近的词条就改它，不要新造一个同义的）。
4. **`.scratch/README.md`**：加一行 `link-emphasis`（形态 `spec`，一句话写实，票数写实数）。

## 评论

- **改了五处**（本票由 Lead 亲手落，不派子代理）：
  - `docs/render.md` 的「可点链接」一节：开头那句改成「**文件**升起文件查看器、**URL 与目录**交给系统
    默认程序」；在「可点就是下划线」之后补一条「**可点就是链接色**」（正文上色、行内代码保持灰、
    引用块保持叙述灰、代码块让语法高亮说话、Markdown 链接的文件目标连标签带回显一起上、URL 目标
    不上）；「打开是宿主侧的动作」改成两条路各说各的（`xdg-open` 那一路 argv 直传、文件那一路开

  - `docs/tui-manual-checklist.md` ㊻：六步（链接色与行内代码的灰、Markdown 链接的文件目标上色、
