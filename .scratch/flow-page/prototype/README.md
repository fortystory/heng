# 右栏「流程」页：形状草稿（PROTOTYPE）

Status: **accepted —— A 等权全图胜出**（2026-10-19，维护者选定）

- **来源**：一次 `/ask-matt` 下的设计讨论。第一版「轨道式纵向流程图」被维护者判为
  「有点简陋」，这一轮补侧注、当前节点子块、循环回边与回合统计，并给出三种**结构不同**
  的形状让他挑。
- **这是 prototype，不是 spec。** 形状定了之后折进 spec，本目录留作一手材料（先例：
  [`../../trace-tab/prototype/`](../../trace-tab/prototype/)、
  [`../../tui-sidebar/prototype/`](../../tui-sidebar/prototype/)）。

## 要回答的问题

右栏宽 42 列（宽屏 60 列）、全高 24 行，顶部还要让出 3 行页签条。在这个预算里，把
**agent 一次回合的循环**画成「当前在哪个节点 + 一句说明」，哪种形状读得动？

## 为什么不是 HTML 原型

这是 Rust TUI，没有浏览器可挂。仓库既有先例是脚本画文本帧、判断形状。UI 原型那套
「浮动底栏 + `?variant=`」在这里的等价物是 `-v a|b|c` 参数。

## 跑

```sh
python3 .scratch/flow-page/prototype/frames.py          # 全部：3 变体 × 3 态 × 2 档
python3 .scratch/flow-page/prototype/frames.py -v a     # 只看一个变体
python3 .scratch/flow-page/prototype/frames.py -w 42    # 只看一档宽度
```

输出同时落在 [`frames.txt`](frames.txt)。脚本对每一行断言显示宽度（中文按 2 列）并断言
总高 24 行，所以帧本身是可对齐的草稿，不是随手画的。

## 三个变体

### A 等权全图（`-v a`）

五个节点同一权重；当前节点展开两行子块；每个已过节点带耗时侧注；工具节点带权限门 /
工具执行的分支树；工具之后有一条 `↺` 回边；底部说明区 + 回合统计。

- **优点**：信息最全，一张图回答「走到哪、花了多久、下一步会不会回环」。
- **缺点**：42 档下每行只剩 40 列，节点名超过 5 个中文字就写不下；子块把当前节点撑成
  3 行，节点多时容易挤。
- **适合**：想把它当「调试视图」读，而不只是状态灯。

### B 环形图（`-v b`）

2×2 四个框（等模型响应 / 流式输出 / 工具调用 / 下一轮迭代），四条箭头首尾相接成一个
闭合回路，上方一行入口（收到你的话 · 准备请求）。

- **优点**：唯一把「循环」画成几何形状的变体。一眼看出 agent 不是流水线。
- **缺点**：信息最粗，没有耗时侧注之外的细节；42 档下框内只有 12 列可用；
  「没有工具调用时直接收尾」这个分支画不出来（只能用说明区补）。
- **适合**：想第一眼就知道「它转了一圈」。

### C 焦点放大（`-v c`）

当前节点一个双线大框，前后各挂一个上下文节点，更早的节点压成一行历史。

- **优点**：「现在在干什么」读得最快，当前节点的分支（权限门、工具命令）都能放下。
- **缺点**：历史最弱，看不到早先几个节点的耗时；空闲态几乎是一个空框。
- **适合**：想让它替代状态行的「在跑」那一格，作为一眼扫过的东西。

## 图例

文本帧里没有颜色，真终端里：

| 字形 | 颜色 | 含义 |
| --- | --- | --- |
| `✓` | MUTED | 已过的节点 |
| `◆` | ACCENT + BOLD | 当前节点 |
| `○` | MUTED | 未到的节点 |
| `│` | MUTED | 节点之间的连接 |
| `├` `└` | MUTED | 当前节点的子块 |
| `┄` `┆` | CHROME | 页签条（框架档虚线） |
| `─` | MUTED | 说明区小节线（内容档实线） |
| `↺` `→` `▶` `◀` `▲` `▼` | MUTED | 回边与方向（新字形，需进符号表） |

页签条上选中的「流程」是 ACCENT + BOLD，未选中的「轨迹」是 MUTED。

## 帧里编码的假设

1. **节点集**（A / C）：收到你的话 → 等模型响应 → 流式输出 → 工具调用 → 回合收尾。
   `准备请求` 与 `等模型响应` 在事件上分不开（`TurnStarted` 到首个 `Delta` 之间），
   所以合成一个节点，它的子块（投影 / 身份 / 裁剪 / 预算预检）是**静态清单**。
2. **数据全部来自 TUI 侧推导**：`RenderEvent::Logged` 的事件相位、`Delta`、`SessionState`
   三态、事件信封的 `at` 时刻。零 agent 改动（A 方案）。
3. **头部的耗时**是「当前节点从进入到现在」；已过节点侧注是「该节点停留时长」。
4. **说明区高度固定**：文案长短不挤动轨道（排版纪律）。
5. B 的「下一轮迭代」是环上的常驻节点，不表达「没有工具调用时跳过它」。

## 决定（2026-10-19）

**A 等权全图胜出。** 这一轮要解决的是「简陋」——A 是三条里唯一把信息补足的：每节点
停留时长、当前节点子块、权限门/工具分支、`↺` 回边、回合统计都在。B 的环形几何是它
独有的优势，但 A 用 `↺` 回边已经表达了「会回环」这件事，而 B 丢掉的分支（没有工具
调用时直接收尾）在 A 里是自然画得出来的。C 的焦点放大可以看作 A 当前节点子块的削弱版。

**未选的两个变体不进产品代码**：B、C 的帧留在 [`frames.txt`](frames.txt) 里作为一手
材料，实现时不再引用。

**A 的定案形状**（进 spec 的输入）：

- 5 节点：收到你的话 → 等模型响应 → 流式输出 → 工具调用 → 回合收尾；
- 当前节点展开至多 2 行子块，其余节点 1 行；
- 已过节点右对齐停留时长；流式输出带已收字数；工具调用带工具名与已跑时长；
- 工具调用之后一条 `↺ 还有工具调用 → 回到「等模型响应」`；
- 说明区贴底、高度固定，文案长短不挤动轨道；
- 回合统计一行：迭代数 · 工具数 · 上下文占比（60 档放宽到输入/输出 token）。

## 进 spec 前还要定的

- 节点名长度上限：42 档下建议 ≤ 5 个中文字。
- 空闲态要不要显示上一回合路径（A 现在显示）—— 会不会与「当前」混淆。
- 高度 < 20 行时的降级：这一轮只画了 24 行，降级阶梯留给 spec。
- 回边的真实判据（`MessageCompleted` 后工具调用列表非空）与动画相位（当前连接线
  `┃` / `│` 交替）留给实现票。
- 右栏第二页的代价：页签条吃掉 3 行，轨迹页跟着少 3 行；是否需要（只加一页之后）。
- 平铺态右栏画哪个会话的流程（预期 = 焦点会话）与历史重播时流程图是否随事件演化。

## 明确不做

- 颜色与字形的最终取值（色板归 `palette.rs`，字形归符号表）。
- 滚动：流程图页固定一屏、当前节点始终可见，不做可滚动的完整图。
- B 方案（agent 里埋旁路信号）——如果维护者要「投影 / 裁剪 / 预算」逐个高亮，才需要它。
