# 右栏「流程」页：agent 循环的实时视图

Status: 4/4 done（票 [`01`](issues/01-rail-tabs-and-flow-placeholder.md)–[`04`](issues/04-degradation-docs-and-checklist.md) 全部落地；ADR 0025）

- **来源**：一次 `/ask-matt` 下的设计讨论 → 形状三选一 → [prototype](prototype/README.md)
  定案 **A 等权全图**（2026-10-19）。帧在 [`prototype/frames.txt`](prototype/frames.txt)。
- **术语**：沿用 `CONTEXT.md` 的**回合（Turn）/ 迭代（Iteration）**、**投影**、**权限门**、
  **右栏**、**轨迹页**、**措辞层**、**语义色板**、**字形语法**、**命中矩形**。
- **推翻**：[ADR 0024](../../docs/adr/0024-trace-lives-in-the-right-rail.md) 的「右栏里只有
  一页 —— 轨迹」那半句：右栏从这一轮起有第二页。ADR 0024 的其余决定（右栏的宽度档、
  `Ctrl-V` 语义、轨迹的宽度来源）一个字不改。

## 问题陈述

1. **运行中的过程不可见。** 轨迹页与转录都是**事后**读的；一次回合进行中，屏幕上唯一的
   状态信号是状态行那个「在跑」的词与月相。用户不知道此刻卡在哪一段：请求还没发出去、
   在等第一段文本、在收流式、在过权限门、还是在跑工具。
2. **等待没有量。** 等模型时没有秒数，流式时没有字数，工具跑着时没有工具名与已跑时长。
   用户只能凭感觉判断「是不是卡死了」。
3. **循环的形状看不见。** agent 循环（等模型 → 流式 → 工具 → 回到等模型）写在
   [`docs/lifecycle.md`](../../docs/lifecycle.md) §4 里，但界面上读不到；用户不知道一次
   回合会转几圈、现在在第几圈。
4. **已有的两处投影都不是这个问题的答案。** 轨迹页按事件逐行记流水，回答「发生过什么」；
   时间轴横带按泳道画段，回答「时间花在哪一档」。两者都太细或太抽象，没有一处回答
   「**现在**在哪一步」。

## 解决方案

右栏从一页变成两页：`轨迹` 与 `流程`，顶部一条页签条（与左栏页签条同种画法）负责切页。
`轨迹` 保持今天的样子（顶部横带 + 账本，整体下移 3 行）；`流程` 是新的**等权全图**：

- 五个节点的纵向轨道：**收到你的话 → 等模型响应 → 流式输出 → 工具调用 → 回合收尾**；
- 当前节点 `◆`（ACCENT + BOLD），已过 `✓`（MUTED），未到 `○`（MUTED）；
- 已过节点右对齐停留时长；流式输出带已收字数；工具调用带工具名与已跑时长；
- 当前节点展开至多两行子块（等模型：拼请求清单；工具调用：权限门裁决 + 工具执行）；
- 工具调用之后一条 `↺ 还有工具调用 → 回到「等模型响应」`，把循环画出来；
- 底部固定高度说明区：当前节点 1-2 句解释 + 本回合统计（迭代数 · 工具数 · 上下文占比）；
- 空闲时轨道不空着：它显示**上一回合**走过的完整路径与停留时长。

数据全部来自 TUI 已经收得到的东西：事件流（`RenderEvent::Logged`）、会话三态、
`MessageCompleted.first_token_ms`（[ADR 0020](../../docs/adr/0020-first-token-time-rides-the-completion.md)）、
`ToolCallCompleted.duration_ms`。**零 agent 改动、零事件 schema 改动。**

## 用户故事

### A. 页签与右栏

1. 作为用户，我想在右栏顶部看到 `轨迹` 与 `流程` 两个页签，以便知道这一栏有两页可切。
2. 作为用户，我想点页签切页（与左栏页签同一手势），以便不用记键位。
3. 作为用户，我想让选中的页签亮品红加粗、未选中暗灰，以便一眼看出自己在哪一页。
4. 作为用户，我想让页签条只在右栏有两页时出现，以便不需要的地方不占行。
5. 作为用户，我想让页签选择活到进程结束（与左栏页签同级），以便切会话时不跳回轨迹页。
6. 作为用户，我想让 `Ctrl-V` 的行为一个字不变（只管开/关右栏），以便旧手势不失效。
7. 作为用户，我想让流程页不接键盘、只让滚轮滚它的视口，以便右栏的键位归属保持现状

12. 作为用户，我想让当前节点在一帧里只有一个，以便「现在在哪」没有歧义。
13. 作为用户，我想让已过节点带停留时长，以便回看这一回合把时间花在哪几步。
14. 作为用户，我想在等模型时看到当前节点旁已等的秒数，以便判断是不是卡死了。

### C. 循环与回合

20. 作为用户，我想在工具调用之后看到 `↺ 还有工具调用 → 回到「等模型响应」`，以便一眼看出

21. 作为用户，我想在回合收尾时看到收尾节点变成已过，并把停止原因画出来（完成 / 取消 /

23. 作为用户，我想在底部看到本回合统计（迭代数 · 工具数 · 上下文占比），以便不用去左栏

24. 作为用户，我想在宽档（60 列）看到更宽的统计（输入/输出 token）与更长的说明，

    终端也能看见「现在在哪」。
30. 作为用户，我想让右栏宽度不够时整栏消失（现有规则不变），以便不会为了流程页挤主列。

### F. 不变量

31. 作为用户，我想让所有人类可见文案仍只由措辞层产生，以便界面改版不把字符串散进渲染
    代码。
32. 作为用户，我想让模型可见文本一个字节都不变，以便前缀缓存不被废掉。
33. 作为用户，我想让事件 schema 不动、不新增事件，以便 `log.jsonl` 与回放不受影响。
34. 作为用户，我想让 plain 与 headless 两个渲染器完全不受影响，以便管道化照旧。
35. 作为用户，我想让轨迹页除「少 3 行」之外行为不变，以便这次改动不碰它的语义。

## 实现决定

### §1 页签与布局

- 新增 `RailTab { Trace, Flow }`，默认 `Trace`（保持现状），存在 `TuiState`（与左栏
  `tab`、`right_wanted` 同一档：**纯视图偏好**，只活一次进程，不落盘、不跨会话、切换
  会话不重置）。**不**进 `View`（它不属于某个会话）。
- `layout::plan` 的 `Regions` 新增两个字段：`right_tabs`（页签标签行，1 行）与
  `right_page`（右栏内容区 = 页签条之下到底边）。页签条本身占 3 行（上下两条 `┄` + 标签行，
  与左栏 `TAB_ROWS = 3` 同一个口径），落在右栏全高的顶部。
- 轨迹页的两个矩形（`right_band` / `right_trace`）改在 `right_page` 内计算：**整体下移 3 行**，
  其余算法不动。右栏的宽度档（42 / 60）、隐藏门槛、`right_divide` 都不受影响。
- 页签条复用左栏那套标签画法（`draw_label_bar`）：未选中 MUTED、选中 ACCENT + BOLD、
  标签之间 `┆`、余下用 `┄` 填满。标签文字进措辞层（`TAB_TRACE` / `TAB_FLOW`）。
- 命中：`HitAction::SwitchRailTab(RailTab)`，命中矩形只记**这一帧真画出来的标签**；
  指针分派在现有顺序里加一段（与左栏页签同层，互不重叠，顺序只为确定性）。
  `TuiState` 记 `right_tabs_rect`，与左栏 `tabs_rect` 同一纪律。
- `draw_right_rail` 改成两件事：先画页签条，再按 `right_tab` 分派到 `draw_trace_pane`
  或 `draw_flow_page`。
- 页签不给键位：`Ctrl-V` 仍只是右栏开关；右栏拿住键盘时（`trace_keyboard`）的键位表
  一个字不改。流程页不接键盘与点击；滚轮按指针归属滚它的视口
  （`.scratch/wheel-routing/spec.md` §2 推翻本条的「不可滚动」）。
- **实现期修正**：点「流程」时把右栏的键盘交还给输入区（`release_trace_keyboard`）—— 流程
  页没有可滚的东西，让键盘停在一个不响应的页上更难解释；切回轨迹不会自动拿回来，`Ctrl-V`
  或点账本才拿。

### §2 数据源与相位（核心）

新模块 `src/render/flow.rs`（与 `timeline.rs` / `panel.rs` / `files.rs` 同层），持
`FlowPanel`；流程页的**模型**（相位、节点、行）全在这里，`tui.rs` 只负责把行画进矩形、
记命中。每会话一份，放进 `View`（与 `timeline` / `panel` 同级）—— 切会话、重播都靠它自然
重建，不另存状态。

数据只来自收得到的通道：

| 输入 | 用途 |
| --- | --- |
| `RenderEvent::Logged` 的 `TurnStarted` / `MessageCompleted` / `ToolCallStarted` / `ToolCallCompleted` / `PermissionAsked` / `PermissionDecided` / `TurnEnded` | 相位切换、工具名、权限裁决、停止原因 |
| 事件信封的 `at` | 各段的进入/结束时刻 |
| `MessageCompleted.first_token_ms` | 等模型段与生成段的精确分界（重播也可用） |
| `ToolCallCompleted.duration_ms` | 工具自身运行时长 |
| `RenderEvent::Delta` | 实时「已收字数」（只影响进行中的显示，不落任何状态） |
| `SessionState` 三态（现有读取路径） | 空闲 / 在跑 / 等人类；`AwaitingHuman` 时工具子块写「等你批准」 |

相位是一个小状态机（决策密集，来自 prototype 的帧）：

```rust
enum Phase {
    Idle,                 // 无回合；轨道定格上一回合
    Received,             // 提交之后、TurnStarted 之前
    Waiting,              // TurnStarted 之后、首个增量之前
    Streaming,            // 首个增量之后、MessageCompleted 之前
    Tool,                 // ToolCallStarted 之后、配对的 ToolCallCompleted 之前
    Closing,              // TurnEnded 到达的那一帧（下一帧即 Idle）
}
```

接口形状（决策密集）：

- `FlowPanel::apply(&mut self, event: &Event, state: SessionState)`：唯一入口，TUI 收到
  `Logged` 就转发一条；非主发言者的事件在这里被挡掉。
- `FlowPanel::frame(&self, width: u16, rows: u16, now: DateTime<Utc>) -> FlowFrame`：
  纯函数，产出头部、轨道行与说明行；`tui.rs` 只负责落格与命中。`now` 由调用方传入，
  所以相位与耗时都能在测试里钉死。

- **只认主发言者的事件。** 流程图画的是主会话的回合：`TurnStarted` / `TurnEnded` /
  `MessageCompleted` / `ToolCallStarted` / `ToolCallCompleted` 都要 `speaker_id ==`
  会话主发言者（`SessionFacts.speaker_order.first()`）才影响相位。执行者与讨论者的同名列
  事件一律忽略 —— 否则嵌套回合会让节点乱跳。
- **「收到你的话」从本地手势开始**：用户提交时进 `Received`；`TurnStarted` 到达进
  `Waiting`。提交到 `TurnStarted` 之间通常不到一帧，但状态机不为它猜。
- **回边是结构，不是状态**：`↺` 那一行**始终画**（表达循环），不随「还有没有工具调用」
  出现或消失。工具调用之后的下一轮里它会随整条轨道重新点亮。
- **一次迭代一个 `TurnStarted`**：`iteration` 字段直接用于头部「迭代 M」；回边行不重复
  计数。回合号用 `View::turn_ordinal`（已有，与轨迹和用量的口径同一个），不另数。
- 工具节点在**每一步**工具调用上刷新（工具名、已跑时长）；「工具阶段」的停留时长取
  首个 `ToolCallStarted.at` → 最后一个 `ToolCallCompleted.at`（跨多次调用累计）。
- **实现期修正**：权限门在子块里是**四态**，不是三态 —— 门直接放行（`Allow` 路径，人没被
  问过）写「已通过」、`AwaitingHuman` 写「等你批准」、裁决写「已允许 / 已拒绝」。「询问中」
  只在问出去到会话三态置上之间的那一小段里成立，不再单列一档（`Gate` 枚举 + 外部
  `awaiting` 合成文案）。
- **实现期修正**：`ToolCallCompleted` 到达后相位**停在工具节点**，直到下一个 `TurnStarted`
  （下一迭代）或 `TurnEnded`。两者之间的真实时间几乎为零；把当前节点跳回上一站（「流式
  输出」）比停住更难解释。
- `TurnEnded.reason` 决定收尾节点的字形与说明：`Completed` → `✓`；`Aborted` → `✗` +
  WARN；`Error` / `BudgetExhausted` / `MaxIterations` / `MistakeLimit` → `✗` + BAD。
- **时长口径**：已结束的段用事件时刻之差（重播也正确）；进行中的段用
  `Utc::now() - entered_at`。等模型段的定格值优先用 `first_token_ms`；流式段的定格值 =
  `MessageCompleted.at - TurnStarted.at - first_token_ms`（`None` 时整段算等待）。
- 历史重播走同一条路径：重放 `Logged` 事件时状态机自然演化，播完停在 `Idle` 与最后一
  回合的定格路径上。`Delta` 在重播里不存在，所以流式字数只在实时显示，定格不显示它。

### §3 排版与降级

固定预算（右栏全高 `h` = 屏幕高）：

```
标签条 3 行（上下 ┄ + 标签行）
头部   1 行：回合 N · 迭代 M          右对齐 ⟳ 当前节点已跑时长
空     1 行
轨道   收到 · 等模型 · 流式 · 工具（+ 至多 2 行子块）· 回边 · 收尾
说明区 贴底、高度固定：小节线 ─ + 1-2 句说明 + 统计 1 行
```

- **42 档**（`RAIL_NARROW`）：节点名 ≤ 5 个中文字；流式节点侧注 `6.1s · 214 字`；
  统计 `2 次迭代 · 1 次工具 · 36%`。
- **60 档**（`RAIL_WIDE`）：统计放宽成 `2 次迭代 · 1 次工具 · 输入 12.4k · 输出 1.8k`；
  说明一句一行；工具子块可多一行「结果待追加」。
- **高度阶梯**（标签条之后的内容行数 `r = h - 3`）：
  - `r ≥ 18`：完整（头部 + 空行 + 13 行轨道 + 说明区 4 行以上）。
  - `14 ≤ r < 18`：丢统计行；说明压到 2 行。
  - `10 ≤ r < 14`：轨道退成窗口，只留当前节点与前后各一个（被裁那一端画 `⋮`）；
    说明压到 1 行。
  - `r < 10`：只画当前节点一行 + 说明一行，说明区不画小节线。
- 说明区高度固定是**排版纪律**：文案长短不挤动轨道，当前节点的位置在相位切换时不跳。
- 空闲态：轨道显示上一回合五个节点全部 `✓` + 各自停留时长；头部 `空闲`；说明区
  「上一回合已收起。等你发一句话。」+ 上一回合统计。
- 颜色只从语义色板取：MUTED（过程）、ACCENT + BOLD（当前节点与选中页签）、CHROME
  （页签条与小节线）、WARN / BAD（收尾异常）。**不新增颜色**。

### §4 字形与措辞

- 新字形进符号表：`↺`（回边）、`→`（说明里的方向）、`├` / `└`（子块缩进，内容档实线）。
  `✓` / `○` / `◆` / `│` / `─` / `┄` / `┆` 都已在表内。
- 所有节点名、说明文案、统计格式进 `wording.rs`（`chinese-ui` 纪律）：节点名
  `FLOW_NODE_*`、说明 `flow_note_*`、统计 `flow_stats_*`、页签 `TAB_TRACE` / `TAB_FLOW`。
  渲染代码里不许出现裸字符串。
- 界面文案用中文；标识符（`TurnStarted`、`first_token_ms`）保持英文，与既有纪律一致。

### §5 文档与不变量

- 新增 ADR `0025`（右栏多页 + 流程页只读事件流推导、不新增事件），并回改 ADR 0024 里
  「只有一页」那半句为「第一页是轨迹」。
- `docs/render.md` 补右栏两页与流程页；`CONTEXT.md` 新立词条**流程页（FlowPage）**；
  `docs/tui-manual-checklist.md` 加真机项（页签点击、颜色、字形对齐、动画相位、
  矮终端降级）。
- **不动**：事件 schema、`log.jsonl`、投影与模型可见文本、plain / headless 渲染器、
  键位表、轨迹页的语义（只少 3 行）、右栏宽度档与 `Ctrl-V`。

## 测试决定

**好测试**：只测外部行为 —— 帧上真的画出了什么（某行某列的文字/字形）与相位推导的
输入输出；不测「某个私有字段等于几」这类实现细节。

**两个 seam，都是现有层**：

1. **整帧 seam（主）**：`TuiState::new(...)` + `Terminal<TestBackend>` +
   `draw_frame`，直接断言帧 buffer 里右栏那些格子。先例：
   `the_viewer_frame_covers_everything_under_it` 那一组帧测试（`tui.rs` 测试模块）。
   尺寸矩阵：`120×24`（左栏 28 + 主列 48 + 右栏 42）、
   `174×24`（右栏 60）、`94×24`（无左栏、右栏 42）、`80×10`（右栏 42×10 降级）。
   覆盖：页签条出现与选中态、三态各自的节点/侧注/说明、空闲态定格、点击切页后的帧。
2. **相位 seam（纯函数）**：`FlowPanel::apply(&Event, SessionState)` 与
   `FlowPanel::lines(width, height, now)`。先例：`TurnRail` 的单测（`turn_rail_rows`）、
   `timeline` 的段单测。覆盖：三态下的相位、`TurnEnded` 各 `StopReason` 的收尾字形、
   权限门裁决、多工具调用、`first_token_ms = None` 的老流、重播（按事件序列喂一遍）。

**其余层不再新开 seam**：布局几何在 `layout` 的现有测试里加断言（`right_tabs` /
`right_page` / 轨迹整体下移 3 行）；措辞在 `wording` 的现有测试里加断言（说明文案、
统计格式、页签文字）。

**真机清单**（`docs/tui-manual-checklist.md`）：42 列里中文节点名的字形对齐、页签点击、
当前节点的颜色对比、矮终端（24 / 16 行）的降级、宽档 60 列的统计行。

## 明确不做

- **§4 那 14 个步骤的逐步高亮**（预检 / 组装 `messages` / 预算预检 / 权限门的允许路径 /
  hook）：这些步骤没有事件，A 方案下只能作为静态清单。要逐个高亮需要 agent 侧旁路信号，
  是另一件事。
- **可滚动的完整流程图**：固定一屏、当前节点始终可见。
- **未选的 B（环形图）/ C（焦点放大）变体**：帧留在一手材料里，不实现。
- **新键位**、右栏页签的键盘切换。
- **讨论会话的轮次图、执行者嵌套的流程图**：只画主发言者的回合。
- **主题 / 配色配置**、truecolor。
- **plain / headless** 的任何改动。
