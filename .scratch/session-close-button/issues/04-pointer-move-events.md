# 04: 指针的移动事件不再被丢掉

Type: implement
Status: done
Part of: ../map.md
Blocked by: —

**要建的：** 终端上报的鼠标移动事件不再被渲染器丢掉 —— 渲染器知道指针此刻停在**哪一条会话**上
（**悬浮目标**），并且**只在悬浮目标变化时**才请求重画：鼠标在同一行里划过不刷屏。

## 验收

- [x] 指针的移动事件进到渲染器的指针入口，不再落进兜底分支被丢弃；渲染器记下指针位置。
- [x] 渲染器能把指针位置翻译成**悬浮目标**（哪一个会话：会话页的行 / 页签条的标签 / 平铺的格）。
- [x] 同一行内连续移动**不产生多次重画**（悬浮目标不变 → 不请求重画）。
- [x] 指针不在任何会话上时没有悬浮目标。
- [x] 按住左键拖动仍然是拖选，**不改变**悬浮目标。
- [x] 现有的点击、滚轮、拖选、复制行为一个字不变（回归）。
- [x] 测试：三种落点各能认出那一条会话；同行内移动不触发重画；指针不在会话上时没有目标；
  拖动不改目标；平铺只认格标题行；列表滚动后悬浮目标跟着当帧命中表重算。

## 依赖

无（可以立刻开工）。决定见 [`../spec.md`](../spec.md) 的「B 悬浮目标与指针事件」与
[关闭这条动作的契约改写](03-grilling-close-contract.md)（洪峰合并那条）。

## 落地注记（2026-10-20）

- **两个新字段**（`src/render/tui.rs:3438` / `:3441`）：`hover`（悬浮目标 = 会话身份）与 `pointer`
  （指针上一次被报到的列行）。纯渲染器状态，不进事件流。
- **移动事件接进指针入口**（`:5511`）：`MouseEventKind::Moved` → `pointer_moved`（`:5519`）。
  兜底分支不再吞它。
- **重画标记**：指针入口原来**无条件**置 `dirty`；现在只有**移动**事件例外 —— 目标变了才置
  （`:5519`）。终端按格去重之后一次横扫仍是上百个移动事件，逐个重画会把界面刷成一片。
- **翻译**（`:5546`）：走**命中表**（`regions.action_at`），与点击同一层。「动作 → 会话身份」这份
  翻译**只有一份**（`:5565` 的 `session_of_action`），点击与悬浮共用：会话页的行
  （`HitAction::SessionRow` + `sessions.hits`）、顶部页签条的标签（`HitAction::TopSession` +
  `sessions.hosted`）、平铺的格（`HitAction::Tile` + `tiles`）。翻译不了的（输入区、状态行、空白）
  就是 `None`。
- **平铺只认格标题行**：非焦点格整格都可点，而悬浮的落点是**会话名**（格标题行），不是格里的
  正文 —— 翻译前多判一句「指针在不在格的第一行」（map 冻结项 9）。
- **当帧重算**（`refresh_hover`，`:5531`）：命中表每帧重填，列表滚动、会话被关掉、切走前台之后，
  指针底下那条会话可能已经变了 —— 悬浮目标按**这一帧**的命中表重算（主循环里在画完一帧之后调，
  变了就再画一帧）。
- **公开只读口**（`TuiState::hovered_session`，`:5584`）：票 05 / 07 / 08 画关闭标记时读它，测试也从
  它观察 —— 悬浮目标是**行为**（指针停在哪条会话上），不是内部细节。
- **测试**：[`tests/pointer_hover.rs`](../../../tests/pointer_hover.rs) 八条：三种落点各一条
  （会话页的行、页签条的标签、平铺的格）、同行内移动不重画、指针不在会话上时没有目标、拖动不改
  目标、平铺的正文不算会话名、滚动后跟着当帧命中表重算。帧级断言照 `tests/render_layout.rs` 与
  `tests/session_page.rs` 的写法。
- **已知的一处冻结**：文件查看器立着时指针全归它（既有纪律），于是那一段时间里悬浮目标是
  **冻结**的 —— 查看器关掉之后它还指着旧会话。票 10（黏住的标记会消失）把这一类清干净。
