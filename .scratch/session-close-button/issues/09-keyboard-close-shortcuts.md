# 09: 两条键位：全局 Ctrl-X 与会话页内 x

Type: implement
Status: done
Part of: ../map.md
Blocked by: 06

**要建的：** 纯键盘也能关会话 —— 任何界面按 `Ctrl-X` 关掉前台那一会话；左栏「会话」页里按 `x` 关掉
焦点行那一会话。

## 验收

- [x] `Ctrl-X` 发出前台那一会话的关闭请求；目标忙碌时走与点标记同一条拒绝路径。
- [x] 会话页内 `x` 发出**焦点行**那一会话的关闭请求（键盘路径作用于焦点行，不是「被点的行」）。
- [x] 空宿主时 `Ctrl-X`、无焦点行时 `x`：**不做事、不提示**。
- [x] 输入区的 `Ctrl-W`（删一个词）不受影响；`x` 不与既有的 `r`（改名）冲突。
- [x] 两条键位写进页内键位提示与文档。
- [x] 键位测试：两条键各自发出对的目标；无目标时不发任何请求。

## 落地注记（2026-10-20）

- **`Ctrl-X` 是终端层手势**：处理放在 `TuiState::key()` 里**层分派之前**（与挂起同一档）——
  任何视图都拦不住它（票面：「任何界面按 `Ctrl-X` 关掉前台那一会话」）。空宿主时**什么都不做、
  也不提示**（`sessions.hosted` 里没有前台那一个就不发请求）。
- **会话页内 `x`**：作用于**焦点行**（`sessions.focused_row()`），不是「被点的那一行」。没有焦点
  行时不做事、不提示。改名模式与过滤输入态下键盘本来就归编辑器 —— `x` 只是那里的一个字符
  （既有分支在前，天然不冲突）。
- **目标正在跑**时走与点关闭标记**同一条**拒绝路径：库层拒 → 提示行两段 + 可点的「切到「…」」。
- **提示行**：输入区那套 `KEY_HINTS` 加一条 `ctrl-x 关闭`，收在**末位** —— 位置就是优先级，而
  这一下会毁掉一个会话，优先级最低是对的（窄档从末位丢起，先丢它）。会话页持有键盘时提示改说
  **这一页**的键位（新增 `SESSIONS_HINTS`：`↑↓ 移动 · enter 切过去 · x 关闭 · r 改名 · / 过滤 ·
  esc 还键盘`）—— 那一刻输入区那套头一条是 `enter 发送`，而键盘不在输入区，提示不许承诺兑现
  不了的事。
- **文件查看器**那一张转发表里 `Ctrl-X` 不发进 nvim（它在更前面就被接走了，那一行只是兜住
  编译）。
- **测试**：[`tests/close_shortcuts.rs`](../../../tests/close_shortcuts.rs) 七条（`Ctrl-X` 关前台
  且先切后关、`x` 关焦点行、空宿主 `Ctrl-X` 不做事、没有焦点行 `x` 不做事、`Ctrl-W` 仍是行编辑、
  改名模式里 `x` 只是文本、提示行写着那两条）。
- **既有测试跟着改**：提示表多了一条 → `tests/wording.rs` 与 `tests/render_layout.rs` 里阶梯的
  宽度档变了（141 列那一档仍是九条，170 列起才看得见第十条）；六处「页顶没有 `关闭`」的断言改成
  「没有 `关闭「…`」—— 键位提示里现在有「ctrl-x 关闭」两个字（`关闭` 那个按钮仍然退场）。
