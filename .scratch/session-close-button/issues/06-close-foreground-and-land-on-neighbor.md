# 06: 关掉前台那一会话后，前台落到相邻

Type: implement
Status: done
Part of: ../map.md
Blocked by: 05

**要建的：** 前台那一会话也能直接关掉；关完之后前台**自动落到相邻的一个会话**（按宿主表顺序取下一个，
没有就取上一个），只剩一个会话时关掉进空宿主态。

## 验收

- [x] 关闭检查**不再拒绝**关前台（那条拒绝理由与文案退场）；忙碌与没装载那两条拒绝仍在。
- [x] 渲染器按宿主表顺序算「相邻」（下一个；没有就上一个），并在目标是前台时**先发切到相邻、
  再发关掉目标** —— 两条请求、顺序固定。
- [x] 库层：先切再关之后，前台指针指向相邻的那一个会话，宿主表少一行。
- [x] 关掉**最后一个会话** → 空宿主态（页签条空、输入区禁用、页顶读数 `0 个会话`）。
- [x] 关掉**非前台**的那一会话 → 只发一条关闭请求，前台不动。
- [x] 平铺态的焦点格（就是前台）被关掉时，焦点格落到相邻格；只剩一格时自动回标签态。
- [x] 忙碌时点标记 → 提示行两段 + 可点的「切到「…」」（不再走「先切走再关」那句）。
- [x] 两组测试：库层（关前台的落点、空宿主态）与渲染层（两条请求的顺序与目标 id）。

## 落地注记（2026-10-20）

- **库层不再拒前台**（`src/session/host.rs`）：`CloseRefusal::Foreground` 变体删掉，
  `close_check` 只剩「在跑」与「不在表里」两条。忙碌与没装载那两条不变。
- **库层不碰前台指针**：前台落到相邻是**切换**做出来的事 —— 渲染层先发「切到相邻」、再发
  「关掉目标」两条请求（顺序固定），库层那边就只是「表里少了一行、task 结束了」
  （spec §17「关闭只从表里移除、不碰前台指针」）。**一处算、一处落**，不会两边各算一次落到
  不同的邻居上。
- **渲染器先切再关**（`TuiState::close_session`）：目标是前台时发**两条**请求 —— 先
  「切到相邻的那一个」（`OpenSession`），再「关掉目标」（`CloseSession`）。目标不是前台时只有
  一条，前台不动。
- **「相邻」只有一种算法**（`TuiState::neighbour_in_host`）：按**宿主表顺序**取下一个，没有就
  取上一个 —— 页签条的标签就按那个顺序排，它也是「下一个会话是谁」唯一的口径。原先另有一份
  「列表顺序的邻居」（`alternative_for`）只服务于提示行，票 06 之后**删掉了**。
- **正在跑的那一行不先切走**：渲染层知道它在跑（内存里的三态，票 22）就只发关闭请求 ——
  切走了也关不掉，还把用户脚下的地板抽走。让库层拒它，提示行给一段可点的「切到「<它>」」。
- **提示行点名被拒的那一个**（`RefusedClose` 只留 `target`）：可点段是「切到「<正在跑的那个>」」
  —— 切过去好在那儿按 ctrl-c 取消（原先它切的是**邻居**，到不了文案说的地方）。前半句从
  「这个会话在前台」改成「这个会话正在跑回合」—— 前台不再是被拒的一条，那句话会骗人。
  库层 `CloseRefusal::Running` 的 `#[error]` 也只留这半句（两处各写一份长文案会各自漂）。
- **平铺回标签态**是既有行为：`rebuild_tiles` 在宿主表只剩 ≤1 个时把 `tiled` 置回 false（票 19）。
  这一票只是把它**验收**掉：关掉一个 → 宿主表只剩一个 → 平铺回标签态。
- **一处已知的不一致（如实记）**：空宿主时**前台指针仍指着那个刚被关掉的会话**（库层不碰指针，
  spec §17）。`CONTEXT.md` 的「空宿主」条说的是「此刻没有前台」—— 两者有出入。这不是本票引入的
  （票 21/32 就是这个语义），要改得动 `foreground` 的类型（`SessionId` → `Option`），留给票 11
  与词条一起定。
- **文档跟上**（Standards 轴点名）：`docs/render.md` 的页顶与「点与切」两段改掉（页顶只剩 `新建`；
  关闭只让掉「正在跑」那一处、前台也关得掉）；`docs/tui-manual-checklist.md` ㊶ 补第 6 条
  （悬出 `✖`、点它关掉那一行、关前台 → 前台落到相邻、只剩一个 → 空宿主、正在跑 → 提示行两段）。
- **测试**：[`tests/session_close_button.rs`](../../../tests/session_close_button.rs) 十一条新增
  （先切后关的顺序与两个 id、非前台只一条、最后一个只一条、正在跑的不先切走、空宿主态（含「先点
  关闭、再推空事实」那一条路）、平铺回标签态、平铺的焦点格落到相邻格、忙碌提示行两段**且点它切到
  哪一个**、取邻的「没有就上一个」）；[`tests/session_host.rs`](../../../tests/session_host.rs) 一条
  改写（「切到邻居再关 → 前台是邻居、表少一行」）＋一条改写（前台不再被拒）。
- **既有测试跟着改**：`tests/session_page.rs` 与 `tests/render_layout.rs` 里「把页顶行滤掉」的判据
  从「含『已装载』」改成「含『新建』」—— 票 05 之后页顶不再有 `关闭`，而会话标题里可能就有
  「已装载」那几个字（拿它当判据会滤掉真会话行）。
- **一条既有测试跟着改语义**：`tests/session_page.rs` 的「关闭被拒时提示行给一段可点的」—— 可点段
  现在点名**被拒的那一个**（原先切的是邻居），断言与注释一并改掉。
- **两处实现与 spec 相抵，如实记**：(1) spec 第 12 条说「渲染器照发请求」，而渲染层知道在跑时
  **不先发切换** —— spec 第 12 条已加实现期澄清。(2) 「输入区禁用」是渲染层内部状态（`muted`），
  帧里**没有字可验** —— 空宿主那条只能验「页区写没有会话」「读数 0 个」「页签条空」三样。
