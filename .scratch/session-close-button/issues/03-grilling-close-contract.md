## 问题

本图把关闭的**目标**从「焦点行」改成「**被点的那一会话**」，并删掉左栏页顶那个 `关闭` 按钮。
既有契约里有好几处是围着「焦点行 + 页顶入口」写的，这一票要把它们改写成一条自洽的新契约。

要定的：

1. **`close_check` 的 `Foreground` 拒绝去掉之后**（`src/session/host.rs:162-191`）：
   - 「关掉前台」之后前台落到**相邻**的一个会话 —— 「相邻」按**宿主表顺序**取下一个、没有就取上一个，
     还是按**平铺格顺序**？两处顺序一致吗（平铺槽位就是宿主表前 N 个）？
   - **平铺态**关掉**焦点格**（焦点格就是前台）之后，焦点格落到哪一格？几何会不会突变
     （2 格 → 1 格，3 格 L 形 → 2 格左右）？
   - **标签态**关掉前台那个标签之后，页签条与主列一起切到哪一个会话？
   - 关掉**最后一个会话** → 既有**空宿主态**（页签条空、输入区禁用）—— 与新形态一致吗？
2. **关掉之后哪些界面跟着换**：输入区（草稿属谁）、状态行、提示行、右栏轨迹、终端标题。
   既有 close 路径（`src/cli/interactive.rs:1066` 起）里已经有一段「前台转移」，
   新形态是**复用**它还是另写一条？
3. **左栏会话页页顶那行删掉 `关闭` 之后剩什么**：读数 + `新建`（`新建` 留不留、空宿主时怎么变）；
   `关闭「<标题>」` 两档文案（`src/render/wording.rs:2409-2416`）随之退场 —— 别的文案里有没有
   引用它（「先切到别的会话再关」那句回执、`关闭` 这个词在别处的用法）。
4. **会话页行的点击语义**：单击行 = 落焦点（交键盘），`Enter` / 双击 = 切前台；`✖` 是**行内**的一个
   命中矩形 —— 点 `✖` 时既不落焦点也不切前台，只关那一行。这条与既有「点谁谁就成前台」不变量
   （`session-tab` 票 20 / 32）怎么并置？
5. **键盘可达性**：确认**不加键位**（本图冻结项 10）—— 但会话页既有键位（`↑`/`↓`/`Enter`/`r`/`Esc`）
   有没有因此变成「能落焦点、却没法关」的半截状态？
6. **被推翻条款的清点**（要一张表，逐条写「旧条款 → 新条款 → 出处」）：
   `session-tab` spec §4（页顶 `关闭` 入口）与 §5、票 07 §3（前台不许关自己）、票 20（点行落焦点
   vs 切前台）、票 32（关闭作用于焦点行、关闭点名、只走鼠标）；
   `CONTEXT.md` 的**宿主表**词条（「关闭只把它从这张表里移除」）与**前台**词条；
   `docs/render.md` 的左栏一节与平铺一节；`docs/tui-manual-checklist.md` 里与关闭相关的走查项。
7. **语义色名怎么取**：关闭按钮的红色叫什么（`DANGER`？`CLOSE`？），值取红还是别的；
   它与 `BAD`（工具失败、会话错误，`src/render/palette.rs:38`）的关系怎么写进色板注释与
   `CONTEXT.md`（`/domain-modeling` 那一路：术语入词条）。
8. **实现落点清单**（交给 `/to-spec` 用，逐条写清文件与函数）：
   - `Moved` 怎么接进 `TuiState::mouse`（`src/render/tui.rs:5481-5488`）；
   - hover 状态存在哪、每帧怎么复位、指针移出窗口怎么清（事实票的结论）；
   - 新增的 `HitAction` 变体（**带 `SessionId`** —— 既有 `SessionClose` 硬编码焦点行，
     `src/render/tui.rs:5749-5753`）与**注册顺序**（关闭按钮必须先于 `Tile` / `TopSession` push，
     否则点它永远是「换焦点 / 切前台」）；
   - `close_check` 的改动与 `src/cli/interactive.rs` 的前台转移；
   - `wording` / `palette` / `CONTEXT.md` / `docs` 的改动面；
   - **真机走查新增一条**：herdr 常态（herdr 默认抓鼠标、本机 `[ui]` 段没设 `mouse_capture`）下
     **悬浮不出现**，连现有点击与滚轮也没有 —— 写进 [`docs/tui-manual-checklist.md`](../../docs/tui-manual-checklist.md)，
     并在 `docs/render.md` 注明 herdr 那侧 `mouse_capture = false` 可以放行。

9. **黏住的 `✖` 怎么清**（[事实票](01-research-mouse-move-events.md) §3 给的三条候选，各有代价）：
   - **焦点事件**：crossterm 有 `EnableFocusChange` / `Event::FocusLost`，但 heng 得多发一串
     `?1004h`（并成对撤销）；终端失焦时清掉悬浮 —— 对「鼠标移出窗口」不生效（失焦 ≠ 移出）。
   - **hover 超时**：比如 N 毫秒没动就收起 —— 代价是**读标题时按钮会闪**。
   - **任意键盘输入即清**：键盘操作后按钮消失（键盘优先）；代价是「鼠标悬着 + 敲键盘」之后要再动一下鼠标。
   要定：**选哪一条（或几条叠加）**，以及超时时长若选它。
10. **事件洪峰怎么合并**（同票 §2 的事实：一次横扫 ≈ 80 个 `Moved`、上界 1920，crossterm 不节流，
    heng **一事件一帧 diff + 一帧终端写**）：
    - 在 heng 侧合并（同一轮事件循环只取最后一个 `Moved`；或只在 hover 目标**变化**时才置 `dirty`）？
    - 合并到哪一层（`TuiState::mouse` 里丢、`tokio::select!` 里节流、还是渲染前判「这一帧的指针位置与
      上一帧相同就不重画」）？三种做法的代价不同。
    - 顺带定：hover 状态在**关掉正在悬浮的那一会话**之后怎么复位（每帧 `regions` 只在画的时候重填，
      `src/render/tui.rs:9424`）。

## 作答

维护者 2026-10-20 两轮访谈（十问）收口。**形态**在
[形态票](02-prototype-close-button-shapes.md)（列账、字形、色名），**终端行为**在
[事实票](01-research-mouse-move-events.md)（谁报移动、密度、黏住）。本票只管**关闭这条动作的契约**。

### 一、契约（逐条）

1. **目标是「被点的那一会话」**，不再是焦点行。三个入口指向同一件事：三处的 `✖`、全局 `Ctrl-X`、
   会话页内 `x`。
2. **允许关前台**（推翻 `close_check` 的 `Foreground` 拒绝）。关掉前台那一会话后，**前台落到相邻的
   一个会话**：按宿主表顺序取**下一个**，没有就取**上一个**；都没有 → 既有的**空宿主态**。
3. **平铺态同一套规则**：焦点格就是前台，关掉它之后焦点格落到**相邻格**（按平铺槽位顺序取下一个，
   没有就取上一个）；只剩一格时，既有行为就是自动回标签态。
4. **实现的顺序：先切后关** —— 先发 `OpenSession(相邻)`（改前台指针），再发 `Close(被关的)`。
   理由（库里查过）：`SessionHost::close_with` **只从表里移除并结束 task，不碰前台指针**
   （`src/session/host.rs:399-409`），前台指针是独立的 `watch::Sender`（`:356-358`）；先切后关
   不会出现「前台指针指向已移除的会话」的中间态。
5. **忙时仍拒绝**（那一会话正在跑回合）：提示行**两段** + 可点入口，沿用既有 `close_blocked` 的形状 ——
   前半句说「那一会话正在跑 · 先取消」，后半句「切到「…」」整段可点。
6. **只读预览会话能关**（既有规则不变），它的 `✖` 与普通行**同色**（红）—— `✖` 回答的是
   「这一下会关掉东西」，与那一行是不是只读无关。
7. **只在盘上、没装载的行不给 `✖`**（那类行本来也关不掉）。
8. **点 `✖` 只关那一行**：不落焦点、不切前台。点行的其余部分仍是「落焦点」（`Enter` / 双击才切前台）。
9. **键位两条**（推翻「关闭只走鼠标」）：
   - **全局 `Ctrl-X`**：任何界面关掉**前台**那一会话（平铺态 = 焦点格）；
   - **会话页内 `x`**：关掉**焦点行**那一会话（与 `r` 改名并列）。
   `Ctrl-W` 已被输入区的 `kill_word` 占用（`src/render/tui.rs:5430`），`x` 在会话页键位表里是空的
   （现有：`Esc` / `↑` / `↓` / `Enter` / `/` / `r`）。
10. **黏住的 `✖` 怎么清**：**焦点事件 + 任意键盘输入即清**。焦点事件 = 多发一串 `?1004h`
    （crossterm 的 `EnableFocusChange` / `Event::FocusLost`）盖「切走窗口」；键盘即清盖「回到键盘工作」。
    代价：终端模式要成对撤销（`enable_terminal_modes` / `disable_terminal_modes` / 挂起恢复三处）。
    **没选 hover 超时** —— 协议里没有「指针离开」事件，超时是唯一能盖「鼠标移出窗口而终端仍聚焦」
    的手段，但它会让读标题时按钮闪。
11. **事件洪峰怎么合并**：**只在悬浮目标变化时才置 `dirty`**。事件仍逐个进（`Moved` 与 `Drag(Left)`
    在事件层已经分得开），但同一行内移动不重画 —— 一次横扫 80 列从 80 帧降到 1～2 帧。

### 四、验收与真机走查（写进 `docs/tui-manual-checklist.md`）

1. 三处悬浮出 `✖`、点它关掉**那一**场（不是焦点行那一会话）。
2. 关掉前台 → 前台落到相邻；平铺态关焦点格 → 焦点格落到相邻格。
3. 忙时点 `✖` → 提示行两段 + 可点的「切到「…」」。
4. `Ctrl-X` 与会话页 `x` 都能关掉目标。
5. 黏住：`✖` 出现后切走窗口（焦点事件）或敲任意键 → `✖` 消失。
6. 一次横扫 80 列**不产生 80 帧**（数帧）。
7. **herdr 常态**：悬浮不出现（herdr 默认抓鼠标）—— 记一条。
8. 拖选**不**把 `✖` 选进剪贴板（三处的 `✖` 都不落在标题字形上：会话页顶替标记列、页签条与格标题行
   在标题前留一列）—— 仍要真机验一次。

### 五、不立 ADR

按「难以逆转 / 无上下文会困惑 / 真实权衡」三条门槛逐条量过：焦点标记退场、关前台允许、`Ctrl-X`、
`palette::CLOSE` —— **改回去都是改绘制与契约代码，成本不高**；hover 靠 `?1003h` 不做降级 ——
**降级随时能加**。没有一条够得上「难以逆转」，**本图不立 ADR**；这些决定住在本票与 `session-tab`
的 spec 改写里。
