# grilling：会话列表的条目、排序与分组

Type: grilling
Status: resolved
Blocked by: 03
Part of: ../map.md

## 问题

把「左栏那一页上每一行长什么样、按什么顺序排、要不要分组」定死，让票 06 的 prototype 有事可画。

**范围级决定已在 charting 冻死**（见 `../map.md` 的冻结项 3、4）：列表只含**本项目及其 git worktree 里跑过的会话**；聚合靠**现场探测**，不造索引。本票不重开这两条。

## 需要定

1. **一行显示什么**：标题（票 01 给的字符串）、相对时间（`3 分钟前` / `昨天 14:02`？）、所属工作区（主检出写什么、worktree 写目录名还是分支名）、用量 / 轮次要不要出现在列表行上（`调用量` 页已经有读数，别重复堆）。给出一张"字段 × 用途"表，并标出哪些是真的会在列表里用到的。
2. **运行时状态标记**：当前前台会话、已在宿主里（后台跑着 / 后台空闲）、后台**待答**（冻结项 8）、工作区**已不在**（票 03 的失效情况）、流损坏。每一态用什么字形 / 颜色（复用语义色板，不新造颜色），以及哪些态可以同时出现。
3. **排序**：按 `log.jsonl` 的 mtime（`SessionStore` 既有口径）还是按"最近活动"（后台跑着的会话可能刚写过、也可能只是驻留）；当前前台会话要不要钉在最上。给一条确定规则与它的平手兜底（既有 `sort_newest_first` 用 id 兜底）。
4. **分组**：平铺还是按工作区分组（主检出一组、每个 worktree 一组）；分组头占几行、28 列档还画不画分组头。若分组，工作区的显示名从哪来（票 03 给的事实：`--show-toplevel` / 分支名 / 目录名）。
5. **空态与少态**：列表为空（本项目还没有历史会话）、只有当前这一场、探测 git 失败导致整页无法聚合 —— 各画哪一句（措辞层 `wording.rs` 出，不散进渲染代码）。
6. **点自己**：点击当前前台会话那一行 = 什么都不做，还是滚到顶部 / 聚焦该行。给一个明确行为（避免"看着能点、点了没反应"）。
7. **上限**：一页装不下时是滚动（左栏既有页都没有滚动，票 06 定）还是截断 + `＋N 场`（照 `todo` 页的溢出写法）。本票只给"要显示多少条"的策略，滚动/截断的形态交票 06。

## 作答

四轮 grilling（2026-10-12，16 问）定下的契约。**只定形状与规则，不含实现代码**；证据一律给 `文件:行`。

### 0. 范围重开（原冻结项 3 作废，已同步改写 `../map.md`）

**列表 = `SessionStore::list_all` 返回的全部会话**，不再限定「本项目 + 它的 git worktree」。

- 起因：旧范围与冻结项 4（现场探测认家族）合起来不可兼得。worktree 被删之后，那场会话的 cwd 探测必然失败，而桶名是不可逆的 FNV 哈希（`src/session/store.rs:258-271`）—— 没有任何办法证明它曾属于本项目。于是「检出已不在」这个标记在列表里永远不会出现，票 02 第 2 条要的那一态是空的。跨机器搬来的会话同理。
- 维护者在 Q6 选了放宽。**这是本票唯一的范围级重开**，其余 charting 冻结项一条不动。
- 后果一：非仓库 cwd 的会话进列表（实测 `/home/forty/code/fortystory/fs-agent` 一个 cwd 就 167 场，票 03 结论 5）。
- 后果二：「属于哪棵检出」退化为**尽力而为的标注**，不再是过滤器。
- 后果三：可达性缺口（实测 281 场 vs 页区 20–40 行）升级为新票 [grilling：会话列表的搜索与过滤](10-session-list-search.md)。

### 1. 一行显示什么

| 字段 | 进列表行 | 来源 | 说明 |
|---|---|---|---|
| 标题 | **是** | 票 01 §2 的权威链（最后一条非空 `SessionTitled` → 前 8 行内首条 `role:User` 消息首行 → id 时间戳渲染 `MM-DD HH:mm`） | 按列截断、尾 `…`，走 `ellipsize_line`（`src/render/width.rs:68`） |
| 相对时间 | **是**（行尾右对齐、定宽） | `log.jsonl` 的 mtime = `Listing.written`（`src/session/observe.rs:54`） | 写法见下表 |
| 检出 | 否（由组头承担） | `git -C <cwd> rev-parse --path-format=absolute --git-common-dir`（票 03 结论 1） | 见 §4 |
| tokens / rounds / messages | **否** | `Listing.tokens` / `.rounds` / `.messages`（`src/session/observe.rs:58-62`） | `调用量` 页已有读数，别重复堆 |
| 会话 id | 否（只在标题落入第三级兜底时作为标题出现） | `SessionId` | 不另占字段 |
| `ended` / `StopReason` | **否** | `Listing.ended`（`src/session/observe.rs:56`） | 不进列表行；终端标题那四段仍在，归票 01 §7 |

**时间写法与列预算**（票 01 §5 要求本票给出 28 / 40 两档的标题列数）：

| 档 | 行宽 | 标记列 | 标题列 | 时间列 | 时间写法 |
|---|---|---|---|---|---|
| 窄 | 28 | 1（永远预留） | 21 | 5 | `刚刚` / `3分` / `2时` / `昨天` / `08-12` |
| 宽 | 40 | 1（永远预留） | 27 | 11 | `刚刚` / `3 分钟前` / `2 小时前` / `昨天 14:02` / `08-12 14:02` |

- 标记列**永远预留**，照 `文件` / `改动` 两页「每行都占满字形列、同层名字严格同列」的纪律（`src/render/tui.rs:8128-8139`、`:8273`）；无标记的行该列画空格。
- 组头占**整行**，成员行**不缩进**（照 `改动` 页的 `changes_header` 与 `changes_line`，`src/render/tui.rs:8258-8301`）。
- 列预算是粗算：票 06 的 prototype 可按真机读数精调。契约只钉「标记列固定 1 列 + 时间定宽右对齐 + 标题吃剩余列并尾 `…`」。
  > **2026-10-12 票 06 精调**：宽档两个数字改过 —— 标题 30 → **27**、时间 8 → **11**。原因是本表的写法里 `昨天 14:02` 就占 10 列、`08-12 14:02` 占 11 列，8 列装不下（票 06 §2）。
- 宽度一律走 `text_columns` / `ellipsize_line`（`src/render/width.rs:13`、`:68`），**不按字节数**（一页中文按字节会折到宽度三分之一，`src/render/pane.rs:554-555` 记着这条）。

### 2. 状态标记表

色板界面域只有那几个角色（`src/render/palette.rs:15-86`），**不新造颜色**。

| 态 | 字形 | 颜色 | 位置 | 数据源 |
|---|---|---|---|---|
| 当前前台 | `▍` | `ACCENT`（`:31`），**不加 `BOLD`** | 行首标记列 | 宿主（本进程就是前台那一场） |
| 后台待答 | `?` | `WARN`（`:34`） | 行首标记列 | **票 04** |
| 后台活跃 | `●` | `PLAIN`（`:19`） | 行首标记列 | **票 04** |
| 后台空闲 | 无 | — | — | **票 04** |
| cwd 目录不存在 | 无（整行 `MUTED`） | `MUTED`（`:23`） | 整行 + 组头 | 现场探测（`cwd` 是否为存在的目录） |
| 流损坏 | 尾 `损坏` | `BAD`（`:38`） | **标题与时间之间**（票 06 回改：原写「时间之后」会顶出栏宽） | 前缀读 / `summarize` 的 `Err` |

- **`BOLD` 留给焦点行**：`文件` / `改动` 两页的焦点行是 `ACCENT + BOLD`（`src/render/tui.rs:8149-8155`、`:8259-8266`），那是「键盘在这一行」；当前前台是「这场就是你在的会话」。两件事，撞色会读混。
- **互斥**：前台 / 后台待答 / 后台活跃 / 后台空闲四态互斥（一场会话只有一个）；`cwd 目录不存在` 与 `流损坏` 可与任意态共存。
- **「cwd 存在但不是仓库」不是失效态**，正常色显示：它只是个非 git 工作目录（`fs-agent` 是现成样本），切得过去。三态里的「探测本身失败」（找不到 `git` / 超时）同理，不占标记。
- 「后台活跃 / 后台待答 / 后台空闲」的**判定与数据源归票 04**，本表只提供字形与颜色。`Observed` 这类名字在 `src/` 里不存在（零命中），现有的「待答」表达只有本进程的 `TuiState.pending`（`src/render/tui.rs:1109`、`:1159-1181`），它不描述别的会话。
- 「当前前台」同时决定 §3 的钉顶：钉的是它**所在的组**。

### 3. 排序

1. **前台会话所在的检出组**（§4）排到组序列最顶；
2. **组间**：按各组内最新一条的 mtime 降序；
3. **组内**：前台那一条第一，其余按 mtime 降序；
4. **平手兜底**：会话 id 降序，照 `sort_newest_first` 的既有写法（`src/session/store.rs:217-223`；id 以 UTC 创建时间戳开头，`:215-216`）；
5. 读不出 mtime 的排最后（`src/session/store.rs:284-288` 按 `UNIX_EPOCH`）。

- **钉顶钉在「组」这一层，不钉在「行」**：列表仍是完整的「组头 + 成员」结构，而前台必然可见（它那组在最顶、它在组内第一行）。把前台那一行拽出分组会造成一个没有组头的孤儿行，与 §4 的规则打架。
- 「按最近活动排」与「按 mtime 排」是**同一件事**：后台跑着的会话刚写过就更新 mtime；驻留但没写的不更新。不必为它另读流尾部。

### 4. 分组

- **按 cwd 各成一组**，组头写**检出目录名**：
  - 家族探测成功（`git -C <cwd> rev-parse --path-format=absolute --git-common-dir` 拿到共同路径，票 03 结论 1）→ 同一个共同路径的所有 cwd 归一组，组头 = `--show-toplevel` 的目录名（worktree 答它自己）；
  - 家族探测失败（cwd 目录不在 / 存在但不是仓库 / `git` 不在 PATH / 超时）→ 按 **cwd 字符串**各成一组，组头 = 该 cwd 的目录名。
- 组头**占 1 行整行**，只写目录名：**不带计数、不带分支名**（照 `改动` 页的 `changes_header`，`src/render/tui.rs:8294-8301`）。分支名（`--abbrev-ref HEAD`，detached 答字面量 `HEAD`）不进行。
- **重名时**退化写尾两段路径（不同路径可能同名，如两个 worktree 都叫 `heng`）：`.../a/heng` 与 `.../b/heng`。
- **空组不画**（照改动页）。
- 窄档 28 列**照画组头**，内容超宽走 `ellipsize_line`。
  > **2026-10-12 票 06 回改**：页区不足 8 行时**不画组头**（降级成平铺）—— 实测页区 5 行时带组头只露出 3 场、平铺 4 场。三级阶梯见票 06 §6。
- 组头**不给命中动作**：不可点、不折叠。

### 5. 空态与少态

- 页签**常驻**，照 `改动` 页「常驻的第四签」的理由（`CONTEXT.md:363`）：页签不该因内容空而出现或消失，它是导航入口。
- 整页文案**只有两句**（措辞层 `src/render/wording.rs`，无参数用 `pub const`、带参数用 `pub fn`，按表面分节，见 `:1-10`、`:2547`）：
  > **2026-10-12 票 06 回改**：空态仍是这两句，但**页顶多一条读数**（`N 场 · M 场在跑`，右端 `关闭`）—— 那是读数不是空态文案，且页区 < 6 行时它整行让位。见票 06 §5、§6。
  > **2026-10-12 票 10 回改**：再加两句 —— 空宿主态的 `没有会话`（票 07 §5）与过滤空结果的 `没有命中的会话`（[票 10](10-session-list-search.md) §3）；页顶那一行在**过滤态下整行让给过滤行**（读数与 `新建` / `关闭` 都让位，命中总数写在那里）。

| 情形 | 文案 | 先例 |
|---|---|---|
| 列表为空 | `还没有历史会话` | `TODO_EMPTY = "还没有待办"`（`wording.rs:2510`） |
| store 读不出（`list_all` 的 `Err` / EACCES） | `读不出会话列表` | `changes_failed() = "读不出改动"`（`wording.rs:2606-2608`） |

- **「只有当前这一场」不另给文案**：当前会话的 cwd 必在当前家族里，它天然占列表一行，那就是一份正常的单行列表。
- **`git` 不在 PATH 不产生整页文案**：列表聚合不依赖 git，只有「认家族」那一步依赖它；退化形态就是 §4 的第二类分组（每个 cwd 一组、组头写目录名）。**「找不到 git」这句不进会话页** —— 有列表可画就不该丢掉它换一句话。
- **单个 cwd 的失效不产生页级文案**：那是行级与组头级的 `MUTED`（§2）。
- 会话页**不需要「正在读取…」态**：轻路径整轮约 10 ms（§8），不值得为它画一帧加载态；若实现上仍有一帧空白，用 `还没有历史会话` 兜底，不新造句子。

### 6. 点击行为

- **单击任何一行**：
  1. 把键盘交给 `会话` 页（照 `take_sidebar_keyboard`，`src/render/tui.rs:5575-5619`）；
  2. 焦点行落在点的那一行（`ACCENT + BOLD`，与 `文件` / `改动` 同档）；
  3. **能切就立刻切过去** —— 目的地写的是「点一条即切过去」，单击就是切换，不另要双击（命中层没有双击识别，`src/render/tui.rs:1600`）。
- **点当前前台会话那一行**：不切换（已经在），只做第 1、2 步 —— 这就是它的「反应」，不留「看着能点、点了没反应」。
- **切不了的行只有两种**：cwd 目录不存在、流损坏。不切，焦点照落，提示行各回一句：
  - `工作区已不在，切不过去`
  - `会话已损坏，切不过去`
- 键位归票 01 §6：`Enter` = 切过去、`r` = 改名（复用常驻 `editor: Input`）、`Esc` = 把键盘还回输入区。

### 7. 条数策略

- **不滚动**，照左栏既有纪律（`todo` 页「不滚动」，`docs/render.md:169`；`改动` 页「这一页没有滚动机制」，`docs/render.md:346-347`）。
- 按页区画满（页区 = 内容行 − 身份 − 页签条，地板 3 行，`docs/render.md:116-118`），**末行写 `＋N 场`**：
  - 全角 `＋`，照 `todo_overflow` 的写法（`format!("＋{hidden} 项")`，`src/render/wording.rs:2503-2507`，绘制 `src/render/todo.rs:136-142`）；
  - `N` = **一条都没露过面**的会话数（含被组头挤掉的那些），照 `todo` 的口径（`src/render/todo.rs:121-133`）。
- **前台会话永远可见**：它那组钉在最顶（§3）、它在组内第一行，溢出不从它那里吃。
  > **2026-10-12 票 10 回改**：**过滤态下这条让位** —— 过滤优先，排序回到 mtime 降序 + id 兜底，前台不在结果里就不显示、不另给提示（[票 10](10-session-list-search.md) §3）。
- **组头也算行开销**：`＋N 场` 的预算要把已画出的组头数扣掉。
- 滚动 / 截断的最终形态归票 06；本票只钉「不滚动 + 末行 `＋N 场` + 前台必可见」。
- **可达性缺口已知**：范围放宽后实测 281 场，页区通常 20–40 行，大部分会话够不着 —— 升级为新票 [grilling：会话列表的搜索与过滤](10-session-list-search.md)，本票不解决。

### 8. 数据来源约束

- **列表行不得走 `observe::summarize`**：它是全量解析（`src/session/observe.rs:77-104` → `read_events`，`src/events.rs:1086`），281 场实测 **155.6–172.2 ms**，切页会卡。
- **走票 01 §4 的那条前缀轻路径**：`list_all`（4.6–5.1 ms，`src/session/store.rs:147-164`）+ 逐条 `metadata().modified()`（1.123 µs/条）+ 前 8 行前缀读（3.7–4.8 ms；形状由票 01 §4 钉死：`BufReader::lines()` + `serde_json::Value`，只取 `SessionStarted.cwd` 与首条 `role:User` 的 `text`）。整轮约 **10 ms**。
- **`list_all` 与 `summarize` 的 `Err` 语义不同**：任一条流坏掉会让 `summarize` 整批 `Err`（票 03 结论 5，一条坏流能毁掉整页），而 `list_all` 只做目录扫描、不读内容 —— 所以一条坏流不毁整页，只体现在那一行的「流损坏」标记上（§2）。
- **绝不走 `EventLog::open`**：它会 `repair_before_append` 补换行 / `set_len` 截断坏尾巴，**改文件**（`src/events.rs:1018-1021`、`:1114-1134`）；列表与派生都是只读动作。
- **不造索引、不落盘缓存**：家族探测与标题派生按票 01 §4 只放进程内缓存。**重算时机**（切页 / 定时 / mtime 变化）归票 06。

### 9. 与其它票的对接点

- **票 04** 提供「后台待答 / 后台活跃 / 后台空闲」的判定与数据源，以及「当前前台是哪一场」这个事实（本进程内目前是单会话假设）；本票只给字形与颜色。
