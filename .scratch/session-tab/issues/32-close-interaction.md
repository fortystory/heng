# 32: 关闭的交互：让「要关哪一场」在点之前就看得见

Type: grilling
Status: open
Blocked by: 21, 31
Part of: ../map.md

**要打通的行为**：想关掉会话页上的某一场时**不必绕路**。现在点 `关闭` 之前，人得先把前台挪到
别处，再用 `↑`/`↓` 把焦点移回目标行 —— 而这两步在屏幕上分不出来（焦点是字重与时间列颜色，
前台是 `▍`），于是关一次会话变成一串没写在任何地方的仪式。

**来源**：维护者 2026-10-12 问「关闭的会话该如何操作？」—— 那一刻他点 `关闭` 得到
`heng: 别关脚下这一场：先切到别的会话再关`。**现状可用**（`↑`/`↓` + `关闭` 真机实测能关掉，
2 场 → 1 场），所以这一票是**优化**，不是缺陷修复。

## 现状（2026-10-12 实测）

- `关闭` 作用于**焦点行**（`HitAction::SessionClose` → `sessions.focused_row()`），而鼠标点
  一行会**连前台一起切过去**（`sessions_click`）—— 于是「点一行再点关闭」永远撞上
  `CloseRefusal::Foreground`：点谁，谁就成了脚下那一场。
- 走得通的只有一条路：点别的行切走 → `↑`/`↓` 把焦点移回目标行 → 点 `关闭`。
- 会话页里 `Enter` 是空键（`Key::Enter => {}`）：键盘切前台**没有入口**，前台只能靠鼠标点。

## 候选方向（先做一次 grilling 定，别在这里定死）

1. **目标可见**：`关闭` 从「一个按钮」变成「`关闭「<标题>」`」那一行 —— 点之前就知道关谁。
2. **键位补齐**：会话页 `Enter` = 切前台、单击 = 只落焦点（现在这两件事被点行合并了）。
3. **拒绝可点**：被拒的提示行给一个可点入口（照退出闸门那条 `还有 N 场在跑 · 切过去`），
   把「先切走」做成一次点击。
4. **空宿主不必绕**：只剩一场时，`关闭` 直接给「关掉它并回到空宿主」（现在必须先 `新建`）。

## 验收（待 grilling 后定稿）

- [ ] 关掉任意一场**非前台**会话是一步操作，不需要方向键
- [ ] 点之前屏幕上能看出关的是哪一场
- [ ] 被拒时说清下一步做什么，而那一步最好可点
- [ ] 四条既有规则一个字不动：前台自己禁止、跑回合拒绝、空闲单击即关不二次确认、只读预览也能关
- [ ] 真机走查路径进 `docs/tui-manual-checklist.md`

## 欠账

- 无。这一票本身就是别处的欠账：票 21 定的「关闭只走鼠标」与票 31 记的「焦点与前台在屏幕上
  难分」在同一条路上叠成了这个仪式。
