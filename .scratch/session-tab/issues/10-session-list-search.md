# grilling：会话列表的搜索与过滤

Type: grilling
Status: resolved
Blocked by: —
Part of: ../map.md

## 问题

列表范围放宽到 store 里全部会话之后（票 02 §0），实测 281 场，而页区通常 20–40 行、**不滚动**、末行只报 `＋N 场` —— 大部分会话够不着。把「怎么把它们找出来」定死。

**范围级决定已由票 02 冻死**：单行条目（标题 + 右对齐相对时间）、按 cwd 分组、组头写目录名、前台所在组钉顶、不滚动 + `＋N 场`、列表行走前缀轻路径。本票不重开这几条。

## 需要定

1. **入口与形态**：左栏页内顶上一行的过滤行？复用常驻 `editor: Input` 的页内搜索模式（照轨迹视图搜索的先例 `src/render/tui.rs:4844`）？还是 CLI 一族（`heng sessions ls` 的过滤参数，照票 01 §6 的 `sessions title` 先例）？过滤后是「只剩命中的行」还是「只剩命中的会话 + 组头保留」？
2. **判据**：按标题子串？按 id 前缀？按 cwd / 检出目录名？大小写与全半角怎么算（轨迹视图的搜索是空格分词、大小写不敏感、各词 AND，`CONTEXT.md:318`）？多个词是 AND 还是 OR？
3. **命中怎么读**：命中在标题里高亮（`HIT` 现在是时间轴的**底色**，`src/render/palette.rs:66`，借不借）？还是只保留行？`＋N 场` 在过滤态下换成 `n 个命中`（照新内容指示器的读法，`CONTEXT.md:291`）？空结果写哪一句？
4. **与分组、钉顶、前台可见的关系**：过滤态下前台钉顶还成立吗（前台那条被过滤掉时怎么办）？组头保留且不因过滤改写（照 `CONTEXT.md:323` 对轨迹视图过滤的规定）？空组画不画？`＋N 场` 还画不画？
5. **键盘与鼠标的分工**：页签条「只走鼠标、从不给键位」的不变量不许破；过滤输入区与页内焦点行谁吃字符（照**选项区** / **输入区**的区域分派，`CONTEXT.md:166-171`）；`Esc` 一次手势退一层（照焦点行的既有纪律，`CONTEXT.md:375`）。
6. **退出还原**：过滤是**渲染器状态** —— 与轨迹视图的过滤同一条纪律：不落盘、不进事件流、不进模型上下文（`CONTEXT.md:322-324`）。退出过滤后钉顶、组序、`＋N` 一律还原，不留下「被过滤过的排序」。
7. **明确不做**：正则、跨会话搜消息正文（那是读全量，与票 02 §8 的轻路径约束冲突）、按时间范围过滤的图形化控件。

## 作答

2026-10-12 定完：两轮 grilling（6 + 3 问）。**能复用的照抄轨迹视图那台机器**（`docs/render.md:581-596`、
`CONTEXT.md:318-324`），不能复用的是判据来源。范围级决定（票 02 冻死的那六条）不重开。

### §1 入口与形态

- **入口 = 页内键盘 `/`**（会话页拿到键盘之后，照轨迹视图搜索的先例 `src/render/tui.rs:4844` 一带）。
  - **页签条仍只走鼠标**（冻结项 10 不破）：`/` 是**页内**键位，与票 06 §7 定的
    `↑`/`↓` / `Enter` / `r` / `Esc` 同族，不是页签键位。
  - **不给第二个鼠标入口**：窄档 28 列的页顶行已经放了读数（16）+ `新建`（4）+ `关闭`（4）
    = 25 列，再加 `过滤` 就 30 > 28，得砍读数或换行。鼠标用户点左栏任意处先拿到键盘
    （票 06 §7），再按 `/`。
- **过滤态复用页顶那一行**：进入过滤后，**整行变成过滤行**，读数与 `新建` / `关闭` 让位；
  退出时整行还原。**不额外吃页区行** —— 票 06 §6 的三级降级阶梯（≥8 / 6–7 / <6 行）一字不动。
- **过滤行写法**：左端 `会话` + 光标（查询串），右端 `23 个命中`。与页顶行「左读数 + 右入口」
  同构，只是右端入口换成命中读数。
- **实时生效**：改一个字符就重筛，没有「按了回车才生效」那一档（照轨迹搜索，
  `docs/render.md:585`）。

### §2 判据

- **字段 = 标题（票 01 §2 的权威链）+ 组头目录名**（票 02 §4 的显示名：家族探测成功写
  `--show-toplevel` 目录名，失败写 cwd 目录名）。
- **切词与匹配**：空格分词、**大小写不敏感**、**各词 AND**（照轨迹视图搜索，`CONTEXT.md:318`）。
- **只在前缀轻路径已经派生好的那份列表上筛**：不额外读盘、不走 `summarize` 全量（票 02 §8 的约束，
  281 场实测 155.6–172.2 ms）；家族探测与标题派生沿用票 01 §4 的进程内缓存。
- **不搜 id 前缀**：id 不进列表行（票 02 §1），搜一个屏幕上看不见的东西没有落点。
- **不搜消息正文**：那是读全量，与上一条约束正面冲突（§6）。

### §3 结果形态与命中读法

- **只剩命中的会话行，组头保留**：组头不因过滤改写、空组不画（照轨迹视图过滤的纪律，
  `CONTEXT.md:323`）。
- **命中总数写在过滤行右端**：直接复用 `wording::hit_count`（`src/render/wording.rs:2009-2011`
  的 `"{hits} 个命中"`，0 也是同一句）；**标题不做高亮** —— 整页都是命中，高亮无处对比。
  `palette::HIT`（`src/render/palette.rs:66`）**与搜索无关**：全仓只有时间轴那一条命中带用它
  （`src/render/tui.rs:9315`），别拿错。
- **末行照旧 `＋N 场`**：命中 50 条、页区 15 行时仍然截断。两个数字各就各位 —— 过滤行的
  「多少个命中」是**筛出多少**，末行的 `＋N 场` 是**这一页放下多少**。
- **空结果写两句**：过滤行右端 `0 个命中`，页区 `没有命中的会话`。这是页区的**第 4 句**文案
  （前两句是空 store 的 `还没有历史会话` / `读不出会话列表`，第 3 句是空宿主态的 `没有会话`）。
- **过滤态下取消钉顶**：票 06 §6 的「前台所在组钉顶、前台必可见」在过滤态**让位** —— 排序仍按
  mtime 降序 + id 兜底，前台不在结果里就不显示、不另给提示（过滤是用户主动缩小范围）。

### §4 键盘与鼠标分工

| 键（过滤态下） | 动作 |
|---|---|
| 可打印字符 / `Backspace` | 进查询串，实时重筛 |
| `↑` / `↓` | 在**命中的行**之间移焦点（跳过组头，同票 06 §7） |
| `Enter` | **接受查询并离开过滤态**（照轨迹搜索）—— 离开后 `↑`/`↓` + `Enter` 才是「切过去」（票 06 §7 不变） |
| `Esc` | 一次手势一层（照轨迹视图的层级顺序，`docs/render.md:572-573`，实现形状见 `trace_escape` `src/render/tui.rs:4880-4892`）：**输入态**下 = 取消这次过滤（丢查询、还原草稿）；过滤已生效但没在输入时 = 清掉过滤（回到未过滤的列表）。两处**键盘都留在页里**，再一下才把键盘还给输入区 |
| `r`（改名） | 过滤态下**不收** —— 先 `Enter` / `Esc` 离开过滤 |

- **草稿复用常驻 `editor: Input`**：进过滤时 `std::mem::take(&mut self.editor)` 把**整份草稿**
  收进 `TraceSearch::draft: Option<Input>`（照轨迹搜索的三个落点：`begin_trace_search`
  `src/render/tui.rs:4927-4937`、`accept_trace_search` `:4942-4948`、取消 `:4953-4961`；
  `TraceSearch` 定义在 `:2332-2352`）；`Enter` 接受时还回、`Esc` 取消时也还回 ——
  「一个绘制件都不新造」。
- 鼠标：点左栏任意处 = 交键盘（票 06 §7 不变）；过滤态下点会话行仍是「交键盘 + 落焦点 + 能切就切」，
  过滤不挡切换。
- **页内键位表只多一个 `/`**，不新增任何 `Ctrl-*`；`Tab` / `Shift+Tab` / `Ctrl-O` 照旧。

### §5 退出还原与归属

- 过滤**是渲染器状态**：与轨迹视图的过滤同一条纪律 —— 不落盘、不进事件流、不进模型上下文
  （`CONTEXT.md:322-324`）。
- 退出过滤后：钉顶恢复、组序恢复（前台组钉顶 + mtime 降序）、`＋N 场` 恢复、页顶行恢复成
  「读数 + `新建` + `关闭`」。
- **归属是进程级，不是每会话一份**：它过滤的是**同一份全局列表**（与会话无关），与页签选择同类；
  **不进票 08 §2 那张 `SessionId → 轻状态` 表**（票 08 §3 列进去的 `trace_search` 是轨迹视图的
  过滤，那个跟会话走）。
- 空宿主态（票 07 §5）下 `/` 照常可用但没有对象：过滤行右端 `0 个命中`，页区仍是 `没有会话`。

### §6 明确不做

- 正则。
- **跨会话搜消息正文**：读全量，与票 02 §8 的轻路径约束正面冲突。
- 按时间范围过滤的图形化控件。
- 命中高亮与 `n` / `N` 命中导航：那是轨迹视图那一族的读法，这里整页都是命中。
- 搜索历史 / 保存的过滤：无先例，且属配置类工作。

### §7 落点与回改

- **左栏键盘分派加会话页过滤态**：`src/render/tui.rs:5575-5619` 的 `take_sidebar_keyboard`、
  `:5787-5794` 的 `sidebar_key`（票 06 §7 已经要求加会话页这一路，本票再加过滤态）。
  会话页**现在还没实现**（`Tab` 枚举 `:8715-8730` 只有 Usage / Todo / Files / Changes），
  所以本票说的「复用」是复用机制形状，不是调用现成函数。
- **新文案进 `wording.rs`**：过滤行标签 `会话`、`n 个命中`（含 `0 个命中`）、`没有命中的会话`。
- **回改票 02 §5**：整页文案从「空态三句 + 一条读数」再放宽到「空态**四句** + 过滤行的命中读数」；
  **§6**：`＋N 场` 与命中读数并存，过滤态下钉顶让位。
- **票 09 的清单再加一条**：`docs/render.md` 的左栏小节要写会话页过滤（入口 `/`、实时筛、
  `Esc` 两层、空结果两句）。

**判据复核**：只产决策，无实现代码；模型可见文本与 `messages` 投影前缀一个字节不动；
plain / headless 渲染器不受影响（会话页只在 TUI，冻结项 12）。

**产物**：本票无独立资产（纯决策）；依据全部落在既有先例与票 01 / 02 / 06 / 07 / 08 的契约上。
