# 25: 场外通知：终端标题的状态段

Type: implement
Status: done
Blocked by: 22
Part of: ../map.md

**要打通的行为**：人在别的窗口干活时，终端标题会告诉他这个进程里有会话在等人答、或者刚跑完一场回合 —— 而当前这一场自己的状态（重放中 / 等你 / 运行中）照旧。

**来源**：[spec.md](../spec.md) §7；决策票 [`11-offscreen-attention.md`](11-offscreen-attention.md)。

## 验收

- [ ] 状态段取值优先级（取第一个成立的）：**后台**有待答 → `N 场待答`；前台重放 → `重放中`；前台待答 → `等你`；**后台**有未读的刚跑完 → `N 场跑完`；前台在跑 → `运行中`；都没有 → 省略整段
- [ ] **N 只算后台**（不含当前前台）→ 单会话时标题与今天**一字不差**
- [ ] 段数与位置不变；丢序表（目标名 → 状态段 → 路径退基名 → 硬截断 40 列）**一字不动** —— 待答信息最后才被丢掉
- [ ] 「跑完」这条**边沿在消费侧从电平快照推**：主循环每帧读全部会话状态与上一帧比对推出 `RunningTurn → Idle`；**不新增通道**
- [ ] 未读寿命：保持到**用户下一次键盘 / 鼠标输入**，或**那一场又开跑**；未读集合住主循环，「已读」由渲染器经既有的上游手势队列回报
- [ ] 不需要额外节流：标题仍只在**真变了**才写 OSC（既有快照比对不动）
- [ ] **不做**：桌面通知（另开一张图）、提示音、按待答调整退出码、`sessions ls` 列「有几场在等」（那是另一个进程，落盘会成第二处真相）
- [ ] 测试：状态段取值表逐条（含单会话回归：与今天的词一模一样）；未读的清除两条路径

## 实现记录（2026-10-12）

- **状态段取值表**（`wording::title_state`，5 参）：后台待答 → 前台重放 → 前台待答 → 后台跑完 →
  前台在跑 → 省略整段。前两档带 N（`TitleState::WaitingBackground(usize)` /
  `FinishedBackground(usize)`），词是 `N 场待答` / `N 场跑完`。
- **N 只算后台**：主循环数的时候把当前前台剔掉 —— 所以**单会话时标题与今天一字不差**（测试逐
  条钉住：`重放中` / `等你` / `运行中`）。
- **丢序表一字不动**：`terminal_title` 那四步（目标名 → 状态段 → 路径退基名 → 硬截断 40 列）
  只是把 `title_word` 的结果从 `&str` 换成 `String`，顺序没碰。
- **「跑完」的边沿从电平快照推**：主循环本来就每 80ms 读一遍全部会话状态（票 22），这一票
  只在同一处比对上一帧 —— `RunningTurn → Idle` 记一条未读，`→ RunningTurn` 把它作废。
  **不新增通道**。
- **未读的清除**：`FrontEndEvent::AttentionSeen`（只有标题上真写着 `N 场跑完` 时渲染器才发
  —— 没未读的进程不该为每一次按键多付一条消息）→ 主循环清空那本账；「那一场又开跑」那条在
  上面那个比对里顺带做了。
- **不做**（票面点名的）：桌面通知、提示音、按待答调整退出码、`sessions ls` 列「有几场在等」。
- 测试：`tests/wording.rs` 加 1 条覆盖整张取值表与单会话回归；既有 4 条按新签名更新。

**欠账**：未读的**两条清除路径**只有渲染侧一半可测（有未读才发 `AttentionSeen`）；「又开跑即
作废」发生在本就无自动化覆盖的 cli 主循环里，票面记着，真机走查记在票 09 的清单里。
