# 25: 场外通知：终端标题的状态段

Type: implement
Status: ready-for-agent
Blocked by: 22
Part of: ../map.md

**要打通的行为**：人在别的窗口干活时，终端标题会告诉他这个进程里有会话在等人答、或者刚跑完一场回合 —— 而当前这一场自己的状态（重放中 / 等你 / 运行中）照旧。

**来源**：[spec.md](../spec.md) §7；决策票 [`11-offscreen-attention.md`](11-offscreen-attention.md)。

## 验收

- [ ] 状态段取值优先级（取第一个成立的）：**后台**有待答 → `N 场待答`；前台重放 → `重放中`；前台待答 → `等你`；**后台**有未读的刚跑完 → `N 场跑完`；前台在跑 → `运行中`；都没有 → 省略整段
- [ ] **N 只算后台**（不含当前前台）→ 单会话时标题与今天**一字不差**
- [ ] 段数与位置不变；丢序表（目标名 → 状态段 → 路径退基名 → 硬截断 40 列）**一字不动** —— 待答信息最后才被丢掉
- [ ] 「跑完」这条**边沿在消费侧从电平快照推**：主循环每帧读全部会话状态与上一帧比对推出 `RunningTurn → Idle`；**不新增通道**
- [ ] 未读寿命：保持到**用户下一次键盘 / 鼠标输入**，或**那一场又开跑**；未读集合住主循环，「已读」由渲染器经既有的上游手势队列回报
- [ ] 不需要额外节流：标题仍只在**真变了**才写 OSC（既有快照比对不动）
- [ ] **不做**：桌面通知（另开一张图）、提示音、按待答调整退出码、`sessions ls` 列「有几场在等」（那是另一个进程，落盘会成第二处真相）
- [ ] 测试：状态段取值表逐条（含单会话回归：与今天的词一模一样）；未读的清除两条路径
