# 28: `Ctrl-D` 不再被静默吞掉，且退出走双击

Type: implement
Status: done
Blocked by: 23
Part of: ../map.md

**要打通的行为**：`Ctrl-D` 永远是「退出」那一个键，而且**按下去一定有反应** —— 立着什么的时候
关掉那一层，空闲的时候第一下只举手、提示行说「再按一次」，第二下才真的走。

**来源**：维护者报告（2026-10-12：「`ctrl-d` 不能正常使用，没有『再次按 `ctrl-d` 退出』这种提示，
也没退出成功」，且屏幕上**什么也没出现**）；[spec.md](../spec.md) §1；票 [`23`](23-exit-gate-and-ctrl-c.md)。

## 验收

- [ ] **静默那一版没有出口**：`pending` 立着时 `Ctrl-D` 关掉那一层（与详情覆盖层同一条纪律），
      问卷仍是被忽略的键（票 05/06，那把手的语义归问卷）
- [ ] `Ctrl-D` **双击**：第一下只举手、出口那一段换成「再按一次 `ctrl-d` 退出」，500ms 内第二下才
      推 `Quit`；过时限自动恢复
- [ ] 四档文案齐：空闲 / 忙碌 × 没举手 / 举着手
- [ ] `Ctrl-C` **作废**那把未兑现的退出手势（一次手势一层），仍然只发 `Cancel`
- [ ] **闸门拒了之后那把举手作废**（`ConsoleRequest::ExitBlocked`）：下一次按下重新从第一下算起
- [ ] 闸门本身一字不动：只拒绝、不自动取消、不代用户做决定
- [ ] 测试：双击两下、取消作废、pending 被关掉、被拒后重新开始

## 实现记录（2026-10-12）

- **根因一（静默）**：`exit_key` 里 `if self.pending.is_some() { return; }` 把 `Ctrl-D` 整条吃掉且
  **不回话** —— 任何问题立着的时候按下它，屏幕上什么也不发生（维护者看到的正是这个）。票 23 说
  「只有一个例外留给问卷」，代码写成了**任何** `pending`。现在：`pending` 立着时按 `Ctrl-D` **关掉
  那一层**（`decline`），只有问卷仍按 spec 被忽略 —— 而问卷自己的页脚正说着那些键。
- **根因二（没有「再按一次」）**：票 23 把「第二下变退出」整个删了。维护者要的就是这一层 ——
  多会话之后误触的代价是**一次按掉几场**。`Gesture::Exit` 与 500ms 窗口一直完好（重放在用），所以
  这一轮把它接回主路径：`exit_hint` 恢复两参数与四档（`EXIT_HINT_IDLE_RAISED` /
  `EXIT_HINT_BUSY_RAISED`），`status_line*` 三个函数的 `raised` 实参也回来了。
- **`Ctrl-C` 作废退出的举手**：取消是一次完整手势。旧语义里 `Ctrl-C` 混按也算第二下（会退出），
  现在它只取消 —— 那就顺手把那把还没兑现的退出手势作废，否则「我按 Ctrl-C 想停下来，结果它顺手
  退出了」。
- **闸门拒绝后清举手**：新增 `ConsoleRequest::ExitBlocked { count, first }`，取代原先松散的
  `notice` + `Attention` 两发（`Attention` 因此只剩别的用处在考虑中）。渲染层收下它就
  `expire_exit_gesture()` + 把会话页交到前台 + 聚焦第一场没收尾的。语义：**被拒之后下一次按下仍然
  只是第一下**。
- 测试：`tests/render_tui.rs` 新增 4 条（双击两下、取消作废、pending 被关掉、被拒后重新开始）；
  `tests/wording.rs` 的出口那条改回四档断言。

## 欠账

- `ConsoleRequest::Attention` 现在**没有发送者**了（它的唯一用处就是退出闸门那个可点入口）。
  `close_refused` 那一族（票 21 的「这一场正在跑回合，先在那一场按 ctrl-c 取消」）也在考虑用同一条
  通道 —— 归票 09 的文档回改一起收，或者删掉那个变体。
- 真机走查记在票 09 的清单第 ⑦ 节。
