# 26: 点一行要真的切过去

Type: implement
Status: done
Blocked by: 20
Part of: ../map.md

**要打通的行为**：会话页上**点一条就切过去** —— 已经在宿主表里的零延迟取回、不在的就装载一场。票 20 把这条路径的两头都接上了，中间那一跳却一直没接上，于是这条端到端路径从第一天起就是断的。

**来源**：维护者报告（2026-10-12）；[spec.md](../spec.md) §3、§6；票 [`20`](20-click-to-switch.md)。

## 验收

- [ ] 主循环收到 `OpenSession { id }` **不留空分支**：就地转成一条宿主表请求，由自己的请求分支接住
- [ ] 切换**不因为前台那一场正在跑回合而丢手势**（回合的 `select` 只收得下它认识的那几个）
- [ ] 新建与关闭走**同一条形状**（就地转请求），三者在同一个纯函数里
- [ ] 纯函数有回归测试：三条会话级手势各转成对应请求，其余手势一条都不转
- [ ] 端到端：点一行 → 主列换成那一场、状态行与退出提示按那一场走

## 实现记录（2026-10-12）

- **`front_to_request(&FrontEndEvent) -> Option<CliRequest>`**：会话级的那三条（切 / 新建 / 关闭）
  在主循环里就地转成一条 [`CliRequest`]，由 `open_requests` 分支接住。这条老路拆掉了：**转发给
  前台那一场、由 `CliActor::gesture` 再转回来**。它有两个代价 ——
  ① 前台那一场正在跑回合时手势落进 `run_one_turn` 的 `select`，只认得 `CycleMode` / `OpenPicker`，
     别的落进 `quit.apply` 那一支被丢掉，于是「切换不因为目标在跑回合而阻挡」那条验收并不成立；
  ② `OpenSession` 一旦在主循环这边被空分支吃掉，那条圈就再没有别的路 —— 点击于是什么都不发生。
- **`CliActor::gesture` 里那三条转接删掉**：主循环直接办之后它们没有发送者了。
- 症状：会话页上点一行没有任何反应（渲染层照常上报 `FrontEndEvent::OpenSession`，票 20 的测试
  钉住的正是那一跳，所以那条路径**测过一半**：上报那半绿，主循环那半没有断言）。

## 欠账

- 主循环逐行的点击路径仍**没有端到端自动化覆盖**（它要真终端与 API key）。两跳由
  `tests/session_host.rs`（装载 + 切前台）与 `tests/session_switch.rs`（投影整块换）分头覆盖，
  中间这一跳现在由 `front_to_request` 的单元测试钉住，真机走查记在票 09 的清单里。
- `forward_gesture` 用 `try_send` 而非 `send`：命令通道（容量 8）满时手势静默丢弃，没有任何回话。
  多连按几次 `Ctrl-C` 就能撞上。改成 `send` 要给主循环一个「等命令」的位置 —— 另记。
