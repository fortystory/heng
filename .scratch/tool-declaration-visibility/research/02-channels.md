# 三条既有通道各能承载什么、要付什么代价

> 产物：[`../issues/02-research-channels.md`](../issues/02-research-channels.md)（research，AFK）
> 只读调研。结论一律给 `文件:行号`。

## 结论先说

1. 请求三样里的 `system` / `messages` 各有一条通道，**`tools` 一条都没有** —— 缺口不在渲染层，
   在「从来没有为工具表开过通道」。
2. 衡今天有**三条**能承载工具声明的通道，**粒度与代价完全不同**：
   - **通道一 · 进流的上下文注入**（`ContextSource` + `ContextInjected`）：会话级、会进模型上下文、
     落盘、可重放；
   - **通道二 · 不进流的渲染通道**（`RenderEvent::Identity`）：会话级、不进模型上下文、不落盘、
     **按当前代码拼**；
   - **通道三 · 详情覆盖层的面**（`FaceId::Schema`）：**per-call**、结构化、只在 TUI 有。
3. **种子列的三个方向分别落在通道三、通道二、通道一（不动）上**；「不动」的第三个方向其实是
   「承认今天只有通道三那一块」。
4. **通道一（进流注入）会把工具表再给模型读一遍** —— 模型本来就在 `tools` 数组里有一份。
   所以它不在种子的三个方向里，但它是通道二的近邻选项，决策票要**明确排除或纳入**。
5. **不管走哪条路，都得先把 `description` 弄出 `tool_schemas()`（`src/cli/probe.rs:325`）** ——
   那是唯一的数据管道。

## 1. 通道一：进流的上下文注入

- 变体：`ContextSource`（`src/events.rs:225-268`），**10 个**。今天产出 9 个；
  `PlanMode` 已经没有任何地方产出，只为读**老**流留着（`src/events.rs:243-247`）。
- 事件：`EventPayload::ContextInjected { source, content }`（`src/events.rs:360-363`），
  `content` 是一段**文本**。
- 产出点：`src/lib.rs:392-407`（`AGENTS.md` 与技能清单，会话开头的**钉住的头部**）、
  `src/cli/interactive.rs:393`（MCP 加载）、`:1197`（压缩摘要）、`:1966`（目标清单）、
  `:2085`（过半提醒）、`src/agent.rs:1521-1525`（讨论者的人物）、`src/lib.rs:959`（压缩摘要）。
- **投影不区分来源**：`src/provider/projection.rs:92-117` 里只有 `Persona` 一条例外
  （只发给被描述的那一位），其余每一种注入都是「用户在对整个会话说话」，原样进 `messages`。
- **位置有讲究**：开头的注入是**钉住的前缀**（投影合并成一条 `user` 消息，
  `src/provider/projection.rs:102-116`），会话中途的注入自成一条消息。

**代价**（若把工具表走这条通道）：

- **模型会再读一遍这张表** —— provider 请求里已经有 `tools` 数组
  （`src/provider/openai.rs:441-455`，三件套 `name` + `description` + `parameters`）。
- **缓存前缀会变长** —— 工具数组**本身就是**缓存前缀的一部分（`src/tools/registry.rs:88-90`、
  `docs/grep.md:148`），再往 `messages` 里塞一份等于把前缀撑大。
- 它会**落进 `log.jsonl`**，于是重放老会话看到的是**当时**那张表 —— 这与通道二正好相反。

## 2. 通道二：不进流的渲染通道（`RenderEvent::Identity`）

- 变体：`RenderEvent::Identity { session, text }`（`src/render/mod.rs:138-141`）。
- 它**不是事件**：不进事件流、不写 `log.jsonl`、不进投影。文档就写在变体自己的注释里
  （`src/render/mod.rs:126-137`）。
- 它**借用注入那条记录的形状**：`src/render/transcript.rs:294-301` 把它变成
  `Block::ContextInjected { source: ContextSource::Identity, content }`，于是转录上那一行与别处
  那排注入同一个画法、`▸` 标记、点得开（`src/render/tui.rs:13557-13577`、`:13896-13914`）。
- **关键：「不进流」是那条通道的性质，不是 `ContextSource::Identity` 这个变体的性质。**
  同一个变体在投影与压缩摘要那边也各有一句人话（`src/context.rs:432`），正因为它**到不了**那里
  —— 那句注释写得很清楚。
- **什么时候摆进去**：会话开跑时**一次**，在横幅之前（`src/cli/interactive.rs:409`）。
- headless **明确忽略**它（`src/render/headless.rs:53`）；plain 会把那一行原样打出来
  （`src/render/plain.rs:207-209`），但 plain 没有详情覆盖层。
- 承载能力：**一段文本**（`text: String`）。要带「19 条声明」就得自己把它变成一个文本块，
  或者新加一条 `RenderEvent` 变体带结构。

**代价**：

- 多一条 `RenderEvent` 变体 + 一个来源名（`src/render/wording.rs:1559-1578` 是一张穷举表）
  + 模型侧那句（`src/context.rs:429-442`）—— 三处都要跟着加一个字。
- 它是**按当前代码拼**的，所以它**自己得把这句话说出来**。系统提示词那条就是这么做的：
  来源名写成「系统提示词（按当前代码拼，不进事件流）」（`src/render/wording.rs:1566`）。

## 3. 通道三：详情覆盖层的面

- 面：`FaceId`（`src/render/tui.rs:14486-14511`），11 个记号；分派表 `DETAIL_FACES`
  （`:14540-14571`）按**记录种类**穷举 7 行，**每一行的第一面就是打开时落的那一面**。
- 工具那一行六面：参数 / 输出 / **Schema** / 计时 / 来源 / 概述（`:14554-14564`）。
- Schema 面读 `SessionFacts::tool_schemas`（`src/render/tui.rs:14659`），
  查不到就写一句「工具表里没有「<名字>」，这次调用的声明查不到」
  （`src/render/wording.rs:549`）。

**代价**：

- 它是**per-call 的**：面挂在一块详情上，而一块工具调用的详情才有 Schema 面。
  「一次看全表」在通道三里**没有落点** —— 全表不属于任何一次调用。
- 承载能力是**结构化**的（它是 `serde_json::Value`，不是一段文本），这是三条通道里唯一一条。
- 只有 TUI 有面这套东西：plain 与 headless 都没有详情覆盖层。

## 4. 两条先例

- **`mcp-support` 票 19**：MCP 的加载结果以**一条上下文注入**的形式进流，那行点得开，详情是
  `DetailKind::Context`（**通吃所有注入来源**，不为 MCP 单开一个详情种类）。
  也就是说：**注入类的东西一律走通道一 + `DetailKind::Context`**（`src/render/tui.rs:14421-14425`、
  `:15919-15924`）。
- **`trace-ledger` 票 24**：给工具那六面补上第三面 `Schema`，而它**只画 `parameters`**。
  收口时补了六条口径（`docs/render.md:544-551`），其中一条就是「表里没有这个名字时写
  「<名字>，这次调用的声明查不到」，不画空面、不编一份 schema 出来」。

## 5. 代价表（给决策票用）

| | 通道一 · 进流注入 | 通道二 · 不进流的渲染通道 | 通道三 · 详情覆盖层的面 |
| --- | --- | --- | --- |
| 粒度 | 会话级 | 会话级 | **per-call** |
| 进模型上下文 | **会**（与 `tools` 数组重复） | 不会 | 不会 |
| 落 `log.jsonl` | 会 | 不会 | 不会 |
| 重放老会话看到的是 | **当时**那张表 | **今天**那张表 | **今天**那张表（查不到就写「查不到」） |
| 承载 | 一段文本 | 一段文本 | **结构化** |
| 落点 | 转录上一行，可点开 | 转录上一行，可点开 | 详情覆盖层的一个标签页 |
| 新增件 | 一条事件 + 一个 `ContextSource` 变体 + 投影分支 | 一条 `RenderEvent` 变体（或复用）+ 一个来源名 + 模型侧那句 | 一面（`FaceId` + 分派表一行 + 画法） |
| 只有 TUI 有 | 否（三个渲染器都有） | TUI 与 plain 有（headless 忽略） | **是** |

## 6. 给决策票用的结论

1. **数据管道只有一处**：`src/cli/probe.rs:325`。通道二与通道三都要先动它；通道一不用动它，
   但要走通道一就得**把整张表序列化进流**。
2. **通道一不是免费的那条**：它让模型多读一遍它已经有的东西，并撑大缓存前缀。
   除非决定「这张表要进模型上下文」（那与本次缺口的方向相反 —— 缺口是**人**看不见），
   否则它应当被**明确排除**，而不是留给实现期临场决定。
3. **「画一行还是画 N 行」是真问题**：19 条内建 + N 条动态，`description` 合计约 5.9k 字符
   （见[工具表那份账](01-tool-table-shape.md)），而通道三的面是 per-call 的 ——
   「一次看全表」在通道三里没有落点。
4. **重放语义必须自己说**：通道二与通道三看到的都是**今天**那张表。
   系统提示词那条已经把这句话写进来源名了；工具声明那条要么照抄这个做法，要么明确说别的。
5. **两个 `SessionFacts` 同名**（`src/render/tui.rs:372` 带 `tool_schemas`，
   `src/session/facts.rs:18` 不带）—— 「改 `SessionFacts` 的形状」这句话要写死是哪一种。
