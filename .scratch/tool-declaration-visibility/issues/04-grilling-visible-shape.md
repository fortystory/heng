# 工具声明在界面上以什么形态可见：三个方向的取舍

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 03

## 问题

**这张图的核心决定**：工具声明（provider 收到的那份 `tools` 表，特别是每个工具的
`description` 用法说明）在界面上**以什么形态可见**。

种子里已经列了三个方向，本票要在它们之间**拍一个**（或者明确拍一个组合，并说清组合的代价）：

1. **补 `description` 到 Schema 面**（通道三，per-call）：`tool_schemas` 改存整份声明，
   那个面先画用法描述再画参数。改动最小、仍在 per-call。
2. **给轨迹加一条会话级记录**（通道二，仿 `RenderEvent::Identity`）：点开看全表。
   与系统提示词对称、一次看全。
3. **只记文档**：把 `docs/render.md` 那句「声明」改成「参数 schema」，承认今天看得到的就是参数。
   不新增任何界面。

**第四个候选要在本票里明确处置**：把整张表当**一条上下文注入**推进去（通道一，
`mcp-support` 票 19 的那条路）。[票 02](../research/02-channels.md) 第 6 节已经把它算过一遍 ——
它让模型**再读一遍**它已经有的东西，并撑大缓存前缀。除非本票明确说出「这张表要进模型
上下文」的理由（那与本次缺口的方向相反：缺口是**人**看不见，模型一直看得见），
否则它要么被**排除**、要么被**明确纳入**，不许留给实现期临场决定。

## 判据（本票要拿来称量三个方向的东西）

1. **看得见的是什么**：只有 `description`？还是 `description` + 参数 schema？
   还是连「这张表有几条」这件事也看得见？
2. **粒度**：per-call（某一次调用那个工具的声明）还是会话级（整张表）？
   per-call 天然答不了「这个会话有哪些工具」；会话级答不了「这次调用的那个工具声明是什么」——
   **这是不是要两张都做**，是本票要回答的。
3. **重放语义**：老会话重开时看到的是**今天**那张表（[票 01](../research/01-research-tool-table-shape.md)
   第 5 节）。界面上**说不说这句话**、在哪儿说（来源名 / 面里的一行 / 文档）？
4. **体量**：`description` 合计 5881 字符、最长一条 896 字符；参数 schema 是 1.5–2 万字符量级。
   「一次看全表」怎么读、读不完怎么办（截断 / 分页 / 只列首行 / 按需点开）？
5. **降级阶梯**：拿不到的时候说什么。Schema 面今天已经有一句「工具表里没有「<名字>」，
   这次调用的声明查不到」（`src/render/wording.rs:549`）—— 新形态要不要有自己的那一句。
6. **模型可见文本零变化**：这次改动的每一个形态都**不许**动模型看到的东西
   （除非本票明确选了通道一）。
7. **代价**：数据管道改一处（`src/cli/probe.rs:325`）是所有形态的共同前置；
   形态本身的增量代价分别是「改一个面的画法」「加一条 `RenderEvent` 变体 + 三处措辞」
   「改一句文档」。

## 作答

2026-10-21 维护者直接拍定（`/implement` 那一轮的问答，**原型没有出帧**）。

**形态：两张都做。**

1. **per-call（通道三）**：工具调用详情覆盖层的那个面先画**用法说明**、再画参数 schema ——
   答「**这次调用的那个工具声明是什么**」。落地在
   [票 08](08-per-call-usage-description.md)。
2. **会话级（通道二）**：转录上一条**可点开**的记录（仿系统提示词那条），点开是全表 ——
   答「**这个会话有哪些工具、每个工具的用法说明是什么**」。落地在
   [票 09](09-session-level-declaration-record.md)。

**两张不是先后，是两种读法**：per-call 答不了「这个会话有哪些工具」，会话级答不了「这次调用的
那个工具声明是什么」—— 各答各的，合起来才把种子那个缺口堵上（`description` 一个字都读不到）。

**通道一（把整张表当上下文注入推进去）：明确排除。** 它让模型再读一遍它已经有的 `tools` 数组，
并撑大缓存前缀（研究 02 第 6 节）—— 而这次缺口的方向相反：**人**看不见，模型一直看得见。
除非有人明确说「这张表要进模型上下文」，否则它不在范围内（[票 09](09-session-level-declaration-record.md)
的正文里也写着这一条）。

**方向三（只改文档措辞）：不选。** 它不堵缺口，只是把今天看得到的说准了 —— 而
[票 10](10-docs-glossary-and-walkthrough.md) 里那部分措辞照样要改（那一句「声明」只对了
三分之一）。

**判据逐条**：

1. **看得见的是什么**：`description` **与**参数 schema 都要看见（per-call 那张面把两样都画出来）；
   「这张表有几条」由会话级那条记录答（来源名里写明多少条）。
2. **粒度**：两张都做（上面已说）。
3. **重放语义**：老会话重开看到的是**今天**那张表 —— **写进来源名**（见
   [05](05-grilling-which-table.md) 与 [09](09-session-level-declaration-record.md)）。
4. **体量**：`description` 合计 5881 字符、参数 schema 1.5–2 万字符 —— **一页多**，所以会话级
   那一档是「转录上一行 + 点开一块可滚的详情，逐条摊开」，不是「转录上摊开」。
5. **降级阶梯**：per-call 那一档查不到时**仍是**那一句「工具表里没有「<名字>」，这次调用的声明
   查不到」（`src/render/wording.rs:549`），不新造措辞；会话级那一档拿不到整表时（不该发生 ——
   表在组装期建好、此后只读）也照实说。
6. **模型可见文本零变化**：**成立** —— 通道一被排除，两张形态都不动 `messages`。
7. **代价**：数据管道改一处（[票 07](07-account-carries-the-whole-declaration.md)）是两张票的共同
   前置；per-call 的增量是「改一个面的画法」，会话级的增量是「一条记录 + 一个详情面 + 三处措辞」。
