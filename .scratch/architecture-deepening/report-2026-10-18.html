Problem. 渲染层把「键盘在谁那里」拆成 11 段早期 return，trace_keyboard 自己的注释 (tui.rs:2639) 已承认这是「第四套「键盘在谁那里」的机制」—— 之前的左栏布尔、两页焦点索引、问卷反显还没退场，又叠了一套。同时 click_at / wheel_at / keyboard_in_the_input 各持一份字段子集。同一个真相三处拼。

  • interface shrinks：TuiState 不再每加一层就多一个 *_keyboard 布尔

  • leverage：5 张 HashMap 收成 1 张

Problem. 渲染层要认的领域事实 10+ 种，每种各有一条 ConsoleHandle::xxx 推命令、对应一条 ConsoleRequest 变体、TuiState 上一个 HashMap 或字段。cli/interactive.rs:572 的 80ms 轮询把「宿主表现在长什么样」算成三份上一帧快照，并拿它做边沿判定。三条规则（未读的寿命、N 只算后台、单会话标题不变）因此只能靠真机走查（tui-manual-checklist ㊶）。

Solution. seam 放在「host 视图」：一个 HostFacts module 算「宿主表现在长什么样」，cli 与 tui 都订阅它的 diff。12+ 个 ConsoleRequest 收成两条「现在」、「事件」。80ms 轮询降到一处。

Wins.

  • leverage：一次投影被两个 adapter（cli/tui）共用
  • locality：标题规则、未读寿命全在 HostFacts 里
  • tests：HostFacts 单一接口，三条规则可单元测试
⚠ 与「单会话」默认行为耦合：把订阅改写前，先在 spec 钉死「宿主表空、单会话、多会话」三态的读数。

首选：把键盘归属收到一处

理由：trace_keyboard 的注释已自陈「第四套」—— 这条 friction 在 10-17 那批 session-panes commit 后从「形态问题」升到「架构问题」，再不收，第五套（平铺态里「焦点格持键盘」）会再来。先例是 ADR 0010，复制它的形状代价低、收益跨三入口（键、鼠、滚轮）。第二选是「同一会话状态，收到一处」，因为它是「按会话切片」这种 10-17 后才冒出的新形态，趁还没长更大收掉；width 半截收与 host 事实投影排在更后。

本轮 未升级的三条（措辞、左栏四页、headless 第三个 adapter）从候选池挪走或转 ADR 引用：pane 平行表已被 Pane::push -> usize 契约自愈；左栏四页与措辞只在「同形态重复」这一档，未到 seam 加宽；headless 第三个 adapter 不变。
