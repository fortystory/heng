# 22: 详情覆盖层与拖选

Type: implement
Status: done
Part of: ../map.md
Blocked by: 19

**要建的：** 浮层的归属在平铺之后仍然清楚。

- `detail_opener` / `detail_rect` / `detail_serial` 从单例**搬进每会话**（今天只有 `detail` 进了
  `SessionLight`，切回旧会话再关可能按错档还原）。
- 覆盖层照旧**整屏居中**（宽度对着整屏量，不缩进格 / 不缩进右栏）；**已开着的覆盖层不因切焦点而
  换归属**；关掉时**按打开方还原**（右栏开的还原给右栏，格内开的还原给那个格）。
- **拖选**仍夹在按下那一刻所属的文本区域里，不跨格；OSC 52 与终端原生选择照旧。

## 验收

- [x] 右栏里点开一条详情，关掉后滚动位置还原给右栏（pty）。
- [x] 格内点开的详情在切焦点之后仍属于原来那个格；关掉时还原给那个格。
- [x] 覆盖层宽度不随格宽变（帧）。
- [x] 拖选不跨越格边界（单元 / pty）。
- [x] 既有详情覆盖层测试全绿。

## 落地注记（2026-10-17）

- `detail_opener` 与 `detail_serial` 跟着会话住进 `SessionLight`（`detail` 本来就在那里）：
  切走收起来、切回原样回来，关掉时仍按**打开方**还原。`detail_rect` / `file_viewer_rect`
  是「上一帧画在哪」的帧值，换会话时置空，免得旧坐标被当成这一帧的。
- 覆盖层宽度本来就读整屏（`layout::detail_width` 用 `self.screen`），所以格宽不参与；测试
  钉住「120 列上框宽 115–116、左缘 2」，并注明平铺态一格只有 45 列。
- **「格内点开的详情」在当前形态下没有入口**：对话视图从不给详情入口（票 12 决定 9），平铺态
  每格也只有对话视图 —— 所以那份归属在实践上就是**右栏 / 轨迹**开出来的那一条：它跟着会话走，
  切焦点不换归属、关闭按打开方还原。这条注记把票面第 2 条与实现的落点对齐。
- 拖选按**按下时刻的区域**夹取（`Drag::press` 带 block 下标），平铺两格是两个 `TextBlock`，
  所以「拖到隔壁格」时头被夹回本格矩形；新增单测钉住这一条。
- 测试：`history_replay` 2 条（覆盖层归属会话 + 关闭还原轨迹、宽度按整屏）、`selection`
  单测 1 条（不跨格）。
