# 13: 右栏容器与轨迹搬家

Type: implement
Status: done
Part of: ../map.md
Blocked by: —

**要建的：** 屏幕上出现**右栏**，轨迹从主列搬进它，按右栏内宽重排。

- 右栏宽度同左栏制（40 / 28 / 隐藏），**标签态取第一个能让主列 ≥ `MIN_WIDTH`(40) 的档**；
  左栏档不动。120 列两侧栏同开 → 右栏 28、主列 50；≥ 122 列右栏才是 40；< 98 列隐藏
  （左栏在 28 档时）。
- 右栏从顶部 2 行开销之下起算、与主列同高；**底部三行（状态行 / 输入区 / 提示行）不跨右栏**。
- 轨迹按**右栏内宽**排版（不再跟主列宽）：40 档保九列时刻、弃行尾用量；28 档是缩略索引
  （不画时刻、不带用量）；组头保留、放弃「并进虚线」、独占一行短写；时间轴只画 Compact 一档。
- 本票不动主列页签条与顶部条（那两件在票 15 / 16）——右栏只是出现在主列右侧。

## 落地注记（2026-10-17）

- **档位判据**：右栏的 40 / 28 按**整屏宽**分（≥ 122 是 40），可行性再看主列地板 40 ——
  于是 94 列左栏收起时右栏仍是 28、主列 65，和票面第二行的 94 帧一致；左栏开着时 94 列
  主列只剩 36，右栏让位。
- **右栏默认开由真进程打开**：`TuiState::new` 里那一份缺省是关，`Tui::run` 组装后
  `set_right_rail(true)`。这么做是为了让两百多条与右栏无关的既有帧断言留在旧基线上；
  票 14 的 `Ctrl-V` 会接上同一份意愿。
- **过渡期**：主列页签条与它的轨迹页还在（票 16 才删），它按右栏的排法画、也仍然接指针；
  右栏最后画、`trace_rect` 归右栏。组头与窄档形态对两边同时生效。
- **删掉的东西**：轨迹行尾的用量尾（`Tail` 机制、耗时段与 `attach_row_tail`）整条移除 ——
  票 08 第 7、8 条要求右栏 40 / 28 都不带用量；用量只留在详情面与「本次发言」合计里。
- 新帧断言 6 条（`the_right_rail_*`、`the_narrow_right_rail_*`、`the_wide_right_rail_*`）。
