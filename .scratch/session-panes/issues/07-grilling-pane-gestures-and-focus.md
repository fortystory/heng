# 平铺的手势与焦点：谁吃键盘、怎么切

Type: grilling
Status: resolved
Part of: ../map.md
Blocked by: 05

## 问题

[平铺的几何与两态布局](05-prototype-panes-layout.md) 给出帧，这一票把**手势**拍定。每条都要落成
一个能在 spec 里执行的句子：

1. **加入与移出平铺**。集合是显式的（冻结项 3）：从哪加入 —— 左栏会话页的一个手势、顶部标签条
   双击、还是命令？移出呢？只剩一个时平铺态怎么办（自动回标签态，还是留着一个大 pane）。
2. **平铺开关**。顶部那条按钮 + 一个快捷键（冻结项 5）：具体键从**未占用的 Ctrl 位**里选。
   今天已占：`O`（左栏）、`V`（主列两页，本图要改指右栏）、`T`（模型）、`C`（取消）、`D`（退出）、
   `Z`（挂起）、`J`（换行）、`K` / `U`（输入区行编辑）；`Ctrl-M` / `Ctrl-I` / `Ctrl-H` / `Ctrl-[`
   在终端里已经被回车 / Tab / Backspace / Esc 占了，`Ctrl-S` / `Ctrl-Q` 是流控 —— 一并避开，
   给出候选与理由。
3. **焦点移动**。平铺里怎么换焦点 pane：方向键、`Tab`、`Ctrl-方向`、数字键？与轨迹账本的选中
   （`↑` / `↓` / `j` / `k` / `[` / `]`）、输入区的光标移动怎么不撞。
4. **切标签**。标签态下切标签的手势（点 + 键）；标签顺序（按创建 / 最近活跃 / 手动排）；焦点在
   第几个时标签条怎么滚。
5. **焦点与宿主表前台指针的关系**。平铺态里「前台」还是不是唯一一个？`SessionHost::switch` 在
   平铺态里做什么；切焦点会不会把别的 pane 的贴底跟随打断；`follow_foreground` 的订阅者
   （`src/cli/interactive.rs` 的轮询、终端标题、退出闸门）在平铺态读谁。
6. **生灭**：平铺态下 `/clear`（翻页）、关闭会话、新开会话、装载旧会话，各自对集合与焦点做什么。
   （更完整的语义可能还在 fog 里，这一票只拍到「够 spec 动手」的那一档。）

## 作答

**（2026-10-17，两轮 grilling 共十一问。三处维护者没走推荐，都在下面写明。）**

**一句话：平铺集合是一个显式的有序列表（≤ 4，按加入顺序）；焦点就是宿主表前台（票 01 那个
`watch<SessionId>`）；两态互切走 `Ctrl-R`，平铺态内换焦点走 `Ctrl-1`…`Ctrl-4`。**

### 手势表

| 动作 | 手势 |
| --- | --- |
| 标签态 ⇄ 平铺态 | **`Ctrl-R`**（维护者选的，不是推荐的 `Ctrl-F`；与 `Ctrl-O` / `Ctrl-V` 同一档的纯视图手势，忙闲都生效）+ 顶部页签条那个按钮 |
| 加入集合 | 平铺态末尾的 **`[+ 加入]` 格**（点它或按同键 → 会话选择器，复用 picker 通道）。**左栏会话页的双击已被「关闭会话」占着（票 32），不拿来当加入用** |
| 移出集合 | 焦点格标题行上的 `×` |
| 换焦点（平铺态内） | **`Ctrl-1` … `Ctrl-4`** 直接跳第 N 格；鼠标点格子 |
| 切标签（标签态） | 点标签；**`Ctrl-左右方向键`**（维护者选的） |
| 集合满 4 个再加 | **拒绝**，提示行给回执（措辞归 [上限、配置与 herdr 默认值的落点](11-grilling-limits-config-and-herdr.md)） |

### 三条语义

1. **顺序**：按**加入顺序**，新加入排末尾（不按活跃度漂）。`[+ 加入]` 格**参与布局**：集合 n 个时
   按 n + 1 格排（1 个会话 → 2 格；满 4 个时它不画）。
2. **焦点就是前台，集合是另一个列表**，两条边界：**集合为空**时按 `Ctrl-R` 进平铺 → **自动把焦点
   加入**（否则第一次永远进不去）；**集合非空而焦点不在里面** → **拒绝进平铺**并提示（维护者的
   选择）。平铺态内的切焦点**只在集合内**发生，几何不因切焦点而变。
3. **生灭**：关闭一个 → 从集合移出、焦点给集合里的下一个；新开 / 装载 → **自动加入**；
   **只剩一个 → 自动回标签态**（帧 05 报的：1 个 pane 的平铺态与标签态几乎一样）；
   `/clear` 翻页 → 新会话**接替**旧会话在集合里的位置。

### 一项新事实（要进 spec 的实现前提）

`map_key`（`src/render/tui.rs:172`）今天**忽略所有修饰键**（只有 `Shift+Enter` 一个特例）——
`Ctrl-Left` 与裸 `Left` 落进同一个分支。所以 **`Ctrl-1`…`Ctrl-4` 与 `Ctrl-左右方向键` 都要求先
给 `map_key` 加修饰判断**；另外 `Ctrl-方向` 在部分终端 / 复用器里可能被吃掉（herdr 的 `ctrl+alt`
弦），这一档要留退路：**鼠标点击始终可用**。
