# 0023. 平铺活在一个进程里，不交给外层 pane

- 状态：接受（2026-10-17）
- 背景：[`.scratch/session-panes/spec.md`](../../.scratch/session-panes/spec.md) 的冻结项 1–3、
  [`.scratch/session-panes/map.md`](../../.scratch/session-panes/map.md)；
  来路是 [`.scratch/session-panes/issues/07-grilling-pane-gestures-and-focus.md`](../../.scratch/session-panes/issues/07-grilling-pane-gestures-and-focus.md)
  与 [`.scratch/session-panes/issues/09-grilling-tab-strip-and-session-page.md`](../../.scratch/session-panes/issues/09-grilling-tab-strip-and-session-page.md)。

## 决定

一张屏幕上的最多四个格**由同一个 heng 进程画**：宿主表里装着几个会话，渲染器就为每个会话
各持一份投影（`View`），平铺态只是「按固定排法把其中几份投影画进几个矩形」。

- 不实现「每个会话一个进程 + 由终端层面拼窗」，也不把平铺委托给 herdr 或 tmux 的 pane。
- 会话之间共享**同一份**渲染器、键盘阶梯、剪贴板与拖选层、状态行、顶部页签条与左栏；
  每会话各持的只是「投影 + 会话事实（cwd / 文件索引 / 名册 / 只读 / 等人类）」。
- 平铺是**渲染器的一种布局态**，不产生进程、不起线程、不改事件流；开关只是 `Ctrl-R` 与顶部
  条上一个按钮，退出时格里的会话照跑。
- 上限 4 来自「排法只到 2×2」，不是来自进程或内存预算；`[ui] tile_limit` 只许 2–4。

## 替代方案

- **每会话一个进程、终端侧分屏**：切前台要跨进程协调键盘与剪贴板，问卷 / 详情覆盖层 / 状态行
  这类「全屏唯一」的东西要么各画各的（屏幕上出现两份），要么另起一层协议；跨会话动作
  （退出闸门、后台待答、`/clear` 接替位置）也都得跨进程。代价比它解决的问题大。
- **交给 herdr / tmux 的 pane**：那样平铺的几何、焦点与键盘归外层，heng 只当一个 pane 里的
  应用；`Ctrl-1…4`、`Ctrl-R`、`[+ 加入]` 这些手势就无处安放，且外层的窗口管理与 heng 的
  左栏 / 右栏会互相挤宽度（herdr 自己还要扣掉 26 列侧栏）。
- **多进程但共享渲染器**：进程边界正是渲染器的边界；拆开之后「每会话一份投影」变成跨进程
  序列化，而它现在只是内存里的一张表。

## 后果

- 一份投影的上限是 `CAP = 20_000` 源行；四个格就是四份，内存随装载的会话数线性增长。
  关闭会话时那份投影与它的表项一起丢掉。
- 渲染器崩溃会带走所有格里的会话 —— 与「一个会话一个进程」相比，故障面更大；换来的是
  所有跨会话动作都在同一份状态里，不存在「两个进程对同一件事各说各话」。
- 宽度重放按焦点格算（票 24）：同一份投影在标签态与平铺态之间换宽度走的是既有重放路径，
  所以两个态里的文字与选中都不漂。
